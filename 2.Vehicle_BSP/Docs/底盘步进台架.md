## 1. 和老板的区别（重要）

| | 老板 | 新板 |
|---|---|---|
| 底盘执行器 | AT8236 + 直流电机 | 张大头闭环伺服，STEP/DIR |
| 脉冲来源 | TIM1 四路 20 kHz PWM | **一轴一个定时器**，硬件出 STEP |
| 编码器 | TIM2/3/4 + PD8/PD9 EXTI | 无 |
| 初始化入口 | `Board_Init()` | **`Board_InitStep6()`** |

**为什么不能走 `Board_Init()`**：它会把 TIM2/TIM3/TIM4 配成编码器模式，而这三个定时器
在新板上是 C / D / 旋转三个轴的 STEP 输出，会被直接抢走。所以 `main.c` 里
`CHASSIS_STEP_TEST` 走独立分支，只做 GPIO + 六个定时器 + 串口。

## 2. 引脚

| 轴 | STEP | 定时器 | DIR |
|---|---|---|---|
| A | PE9 | TIM1_CH1 | PE7 |
| B | PE6 | TIM9_CH2 | PE8 |
| C | PA0 | TIM2_CH1 | PE10 |
| D | PB0 | TIM3_CH3 | PE12 |
| 旋转 | PD12 | TIM4_CH1 | PE13 |
| 升降 | PA6 | TIM13_CH1 | PE14 |

A/B/C/D 是原理图的网络名，**前后左右要上板转一下才能定**（老板上 A/B 是 U2、C/D 是 U3，
新板不保证同侧）。2026-11-03 台架已确认：A=前左、B=前右、C=后左、D=后右。

底盘四路 nEN 并成一根：**PD3（低有效）**，不能单独禁某一个轮子。

2026-11-09 起旋转/升降的独立使能也由固件驱动（此前 PC8/PC9 完全没配，只靠板上 10 k 上拉）：

| 网络 | 引脚 | 管谁 |
|---|---|---|
| EN | PD3 | A/B/C/D 四路 |
| EN1 | PC8 | 旋转 |
| EN2 | PC9 | 升降 |

三根都是低有效，上电默认失能；`E 0` / `E 1` 一次开关三根（`board_step6.c` 的 `en_pins_write()`）。
注意 `M` / `D` / `J` / `A` 只认 `a`～`d`，**旋转/升降目前没有任何命令能驱动**，
这三根使能配上了也还不会让它们动（要挂命令见 `AGENTS.md` 第 11 节 D 项）。

## 3. 命令（USART1 有线口或 UART5 蓝牙，115200）

> **2026-11-03 补蓝牙命令口**：原来只读 USART1，蓝牙收到的字节一直没人取——
> "配对了、发指令没反应"多数就是这个原因。现在两口都收、各自独立拼帧，
> **回复走命令来的那个口**；点动完成/超时的异步消息发给最近一条命令的来口。

```
?  /  S            状态
H  /  HELP         命令表
P                  引脚表
E 0|1              三根 nEN 使能（底盘 PD3 + 旋转 PC8 + 升降 PC9）
F [hz]             满速频率（默认 8000）
M <a-d> <permille> 单轮速度 ±1000
MALL <permille>    四轮同速
L <permille>       麦轮左移（A-,B+,C+,D-）
R <permille>       麦轮右移（A+,B-,C-,D+）
A <deg>            原地转，+逆时针 / -顺时针（开环）
D <a-d> <0|1>      单轮方向
J <a-d> <steps> [hz]  点动 N 步
TASK               跑 WHEEL 的比赛路线表（开环）
STOP               全停（TASK 一起取消）
```

约定：**上电不发脉冲、四路失能**；未使能时 `M`/`MALL`/`J`/`L`/`R`/`A`/`TASK`/`ROT`/`LIFT`/`CYC` 一律回 `ERR not enabled`。

机构命令不在这张表里：旋转台 `ROT <deg>`、升降台 `LIFT <pulses>`、夹爪 `ARM`、载物台 `PLT`、
任务循环 `CYC`，见 [机构指令：升降/旋转/舵机](机构指令_升降旋转舵机.md)。

**转身 17 → 7 → 6 次，步数 38 → 28 → 27**（2026-11-11 删掉收车那次 180°，见下表），
7 个航点位置逐段复算过，与原表一致。

|---|---|---|---|
| 发车 | (0, 0) | 0 朝南 | 先右挪 150 mm 让开墙 |
| W1 | (-150, -1050) | 0 朝南 | 扫码 |

两次 180° 掉头改成 `BACK`（倒车与直行同速，掉头 4.1 s 等于白送）。剩下 7 次转身只用来
对正工位。旧实现靠编码器判距、HWT101 判绝对角；本 Target **没有这两样**，所以是开环计步：

| 步骤 | 做法 |
|---|---|
| FWD / BACK / LEFT / RIGHT | 毫米换成步数，四轮按麦轮符号跑到步数停 |
| TURN_ABS | 指令航向（0=发车车头，正=逆时针）算最短转角，不是实测角 |
| WAIT | `HAL_GetTick()` 非阻塞等 |
| RESET | 只把指令航向清零（表里目前没有这一步） |

代价是**侧移变多**：9400 mm 走左右、5800 mm 走前后。所以横移速度从 240 提到 **400 mm/s**。
旧车 2:1 的比值是直流电机带不动横移留下的，闭环步进没有这个限制；不提的话整条路线反而更慢——
9400 mm 侧移在 240 下要多花 20 s，正好把省下的转身时间全吃回去。

标度在 `App/Inc/chassis_config.h` 参数区：16 细分（`CS_STEPS_PER_REV`=3200）、
**轮径 80 mm**（`CS_WHEEL_CIRC_UM`=**251328**，2026-11-11 换轮后从 75 mm 的 235620 改过来）、
自旋半径 L=207 mm（2026-11-08 按目测 `A 90`≈100° 从旧车 225 mm 缩过来；L 是几何量，不随轮径变）。
⚠ 换轮当天的临时补偿（把 `CS_MAP_QR_DROP_MM` 改成 1000、`CS_MAP_RAW_DROP_MM` 改成 1750）
在标度改对后必须改回场地真实值 **1050 / 1850**，否则会双重补偿、整体走短约 6%。
2026-11-08 调速：原 600 / 300 / 200 → 试到 800 / 450 / 400 实测太快，前后回落到**原值的 80%**；
横移是新路线的主力轴，单独定在 400（原值 300 的 133%），没跟着打八折：

| 段 | 常量 | 线速 | 步进频率 | 转速 |
|---|---|---|---|---|
| 直行 / 后退 | `CS_TASK_FWD_MM_PER_S` = 700 | 0.70 m/s | 8914 Hz | 167 rpm |
| 左右横移 | `CS_TASK_STRAFE_MM_PER_S` = 400 | 0.40 m/s | 5093 Hz | 95 rpm |
| 原地转（`A` 共用） | `CS_TASK_SPIN_MM_PER_S` = 160 | 轮缘 0.16 m/s | 2037 Hz | 39 rpm → 44.3 °/s，`A 90` 约 2.0 s |

速度只决定"跑多久"，不进步数算式，所以三档怎么改都不影响 `L` 和轮径的标定。
细分或轮距不对，整条路线按比例偏。

**每段动作走三段速度**（2026-11-08 加；2026-11-11 参数改为 `CS_MOVE_RAMP_PERMILLE` = **120**、
`CS_MOVE_RAMP_UP_MS` = **350 ms**、`CS_MOVE_RAMP_UP_STEPS` = **12**）：
起转 12% 频率 → 恒速 → 收转 12% 频率。原因见 §6：STEP/DIR 模式下驱动器不插补，
0 → 一万 Hz 的阶跃会跟丢或报过载，一万 Hz 直接断电又会让四个轮子同时打滑——闭环伺服
管得住转子，管不住轮地。判停按每段实际频率分段积分，斜坡不改变总步数。

> **2026-11-11 为什么再放缓**：旧参数下起步第一拍是 0 → 40% 巡航频率的**阶跃**
> （横移 ≈0.16 m/s、直行 ≈0.28 m/s），那一下就是起步甩角的来源；S 曲线只管 40%→100%。
> 改成 120‰ 后起步阶跃 ≈0.05 m/s。斜坡时长还会**按距离缩短**（下限 `CS_MOVE_RAMP_MIN_MS`=80 ms），
> 保证短段（150 mm 对齐）不会被两段斜坡吃光。代价：每个动作的加减速各多 150 ms，
> 整条约 +4~6 s；下表"斜坡"那一行是旧参数的数字，已不代表现状。

### 3.0 permille 与"最大速度"

- **1000‰ = `F` 设的满速，不是硬件极限**：当前 `F 8000`（默认）→ 1000‰ = 8000 步/秒。
  按 16 细分、200 步/转、**80 mm 轮径** ≈ **0.63 m/s**。
- **`F` 的默认满速仍然够用**：自动直行是 8914 Hz，略高于默认 `F 8000`，所以只影响
  `MALL` 这类按 permille 的手动命令；自动路线用的是绝对频率，不受 `F` 限制。
  想让 `MALL 1000` 跑满 0.70 m/s，把 `F` 抬到 9000 以上。
- 固件硬上限 `STEP6_HZ_HARD_LIMIT = 40000 Hz`（再高按注释 42 步进会丢步）；
  驱动器/步进本体还有自己的最大转速与输入频率上限，以张大头实际配置为准。
- 想更快就先 `F` 抬满速，再按 permille 跑；速度上去电流也上去，
  12V 电池供电时留意驱动器和绿灯/温度，别一上来就 1000‰。

### 3.2 麦轮横移（L / R）

滚轮 X 形布置的标准麦轮签名（沿用 WHEEL 在旧车上验证过的方向约定，vy 正 = 车体左侧）：
`vy = (−FL+FR+RL−RR)/4` → 左移四轮符号 **A(FL)−、B(FR)+、C(RL)+、D(RR)−**，右移整体取反。

验证顺序（12V 电池、车能落地后）：
1. `E 1` → `MALL 300` 前进一段、`STOP`；
2. `L 200` 慢速左移——车头不动、车体向**左**平移，四轮同时转、方向两两相反（A/D 反于 B/C）；
3. `R 200` 右移应完全镜像；`STOP`。
如果出现"车在转圈/只有轮子转、车身不动"，多半是滚轮布置不是标准 X 形，
或者装车位映射有误——把现象记下来，横移符号在 `L`/`R` 命令里改一处即可。

原地转是 `A <deg>`（2026-11-08 补，沿用 WHEEL 的名字）：`A 90` 逆时针、`A -90` 顺时针。
开环计步。2026-11-08 目测 `A 90`≈100°，`CS_SPIN_L_MM` 从 225 缩到 203、现场再微调到 207 才不偏。再偏按「指令角/实测角」同比改。

### 3.1 蓝牙没回应，按这个顺序查

| 现象/检查 | 判断 |
|---|---|
| 复位后马上发指令没回 | 车板复位后 HC-05 主机要 1~2 s 才重连上；等 PC 侧听到/看到连接恢复（或从机 LED 双闪=已连接）再发 |
| 发 `?` 仍无任何回复 | 换有线 USART1 发 `?`。有线有回 = 固件在跑，问题在蓝牙链路；有线也没回 = 烧错 Target / 串口选错 |
| 链路通但一个字节都进不来 | 接线没**交叉**：PC12(MCU TX)↔模块 RXD、PD2(MCU RX)↔模块 TXD；确认插的是 `SPARE` 4P 座（1=PC12、2=PD2、3=GND、4=5V），别插成 `PING`/`PI` |
| 有回但乱码 | 波特率不一致：固件 115200，模块 `AT+UART` 必须也是 115200 |
| 有连接但指令像被丢弃 | **2026-11-08 起蓝牙口不要求换行**：静默 50 ms 也算一行结束（`CS_LINE_IDLE_MS`）。有线口仍然只认 CR/LF——PC 终端边打边发，加空闲断帧会把一条命令切成两条 |
| 回 `ERR command too long` | 一行超过 39 字节（`CS_CMD_LEN` = 40）。多半是前面若干条不带换行的命令堆在同一个缓冲里，堆到第 40 个字节就冲爆；**报错后这一行整行丢弃，接着发一条正常命令即可**，不用复位 |
| 遥控无规律丢字节 | 用 `S` 命令看不了丢包，改发 `?` 连发几次看回复是否稳定；串口板过热/共地不良也会这样 |

## 4. 8000 Hz 是什么速度

按 16 细分、200 步/转、轮径 80 mm：

- 8000 步/秒 = 2.5 转/秒
- 周长 251.3 mm → **约 0.63 m/s**

和 `WHEEL` 那边 0.6 m/s 的直行目标是同一量级，方便对照。
如果实际跑起来明显比预期慢/快，说明细分设置或轮径假设不对，先量再改。

| A | 前左 | 轮子**倒转**（推车向后） |
| B | 前右 | 正转（推车向前） |
| C | 后左 | **倒转**（推车向后） |
| D | 后右 | 正转（推车向前） |

判读：左右轮镜像安装的正常现象。固件方向表已把 **A/C 取反**，
改完后 `J` 正数 = 四轮一起推车向前；整车方向再反（换车布局）时
改 `board_step6.c` 的 `STEP6_DIR_INVERT_*`，不要动接线。

## 6. 已知限制

- **点动是开环估算**：步数 = 频率 × 时间，靠 `HAL_GetTick()`，不是真计数。
  只用于"走一小段看方向"，不能当定位。
- 改速度时会先停通道再重配 PSC/ARR，中间有几十微秒的空档；斜坡每一档的切换都会踩到这个空档
  （12 档 = 每段动作 48 次通道停/启，间隔 29 ms，对 5 kHz 的步进脉冲影响可以忽略）。
  闭环伺服会把这段空档补回来，但**斜坡仍是离散档位、不是连续加减速**，真要顺滑还得换成
  "改 ARR + 保持 CCR 比例"的做法（见 §6）。
- **没有编码器也没有陀螺**：三段加减速只解决"跟得上、不打滑"，打滑真发生了没人知道。
  落地后按"指令角 / 实测角"复测一次 `A 90`，确认提速没有把 90° 改坏。
- 16 位定时器在极低速（<约 1.3 Hz）下 PSC 也不够用，会返回 `HAL_ERR`。

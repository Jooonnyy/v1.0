## 0. 结论摘要（先看这个）

**编码器 + 陀螺仪只能做"粗定位"，做不了赛题要求的"把物料放进圆环"。** 两个硬指标决定的：

| 赛题要求 | 需要的精度 | 编码器 + 陀螺仪能做到吗 |
|---|---|---|
| 不越出车道（车道 400mm、车宽 210mm） | 横向 < ±95mm（理论），实操要留足余量 → **< ±30mm** | 勉强（短程 2~5cm），**卡在边界上** → 需要视觉/超声纠偏 |
| 绕开随机摆放的 φ50 障碍 | 横向机动约 ±70mm | 不够 → **必须实时感知避障，不能盲走** |
| 物料放进 **1 环（15 分，φ+3）** | **< 1.5 mm** | **绝无可能** |
| 物料放进 **2 环（10 分，φ+8）** | **< 4 mm** | **绝无可能** |
| 回到启停区（2 分，300×300） | ±150 mm | 够 |

所以定位必须做成**两段式**：

1. **粗定位**（本文档的主角）：编码器 + 陀螺仪 → 把车带到目标区域前，误差 **±3~5cm**；
2. **精定位**（本文不展开，但**必须做**）：朝下视觉 / 机械导向 / 末端自适应 → 把物料压进圆环，误差 **< 4mm**。

⚠ **现有机械设计里摄像头是"前倾 30° 朝前下方"装在升降滑块上的，看不到正下方的圆环** ——
这是放置精度的最大缺口，必须先解决（赛题明确"仅允许垂直向下补光"，说明朝下看是允许的）。

⚠ **还有一条会直接判死的规则**：物料底面一旦接触地面就算放置完毕，**再推行移动该物料 → 本轮比赛结束**。
所以"靠推着把物料挪进圆环"这条路是堵死的：要么一次放准，要么加机械导向。

## 2. 坐标系与单位约定

- **车体坐标系**：x 向前、y 向左、θ 逆时针为正（右手系）。
- **世界坐标系**：上电（或复位）时刻的车体坐标系。原点 = 当时的位置，θ = 0 = 当时的朝向。
- **单位**（一律带后缀，见 `AGENTS.md` 第 3 节）：

| 量 | 单位 | 后缀 | 说明 |
|---|---|---|---|
| 位置 | 微米 | `um` | 全局用 um，避免小数；量程 ±2.1e9 um = ±2147 m，够用 |
| 航向 | 0.001 度 | `mdeg` | ±180000 = ±180° |
| 线速度 | 微米每秒 | `um_per_s` | |
| 角速度 | 0.001 度每秒 | `mdps` | |
| 轮速 | 计数每秒 | `counts_per_s` | 速度环用它，不用物理单位 |

> `counts_per_s` 这一行已补进 `AGENTS.md` 的单位词表。

**符号约定**：`Encoder_Counts()` 返回的计数已按 `ENCODER_x_SIGN` 归一化，
**正数 = 该轮向前滚动**。轮子正转时对应计数必须增大（第 4 节实验 1 标定）。

## 3. 数学（这是实现的核心）

### 3.1 编码器计数 → 车轮位移

```
轮周长 WHEEL_CIRCUMFERENCE_UM = π × 直径
ds_um = Δcounts × WHEEL_CIRCUMFERENCE_UM / WHEEL_COUNTS_PER_REV
```

当前参数：**麦轮直径 70 mm**（2026-10-27 实测，固件 `WHEEL_DIAMETER_MM = 70`）、1320 counts/rev

```
轮周长 = 70000 × 355 / 113 = 219911 um
每计数 = 219911 / 1320 = 166.6 um/count      即 0.1666 mm/count
```

> ⚠ **有效轮径仍建议手推标定**：70 mm 是卡尺量到的直径，加载后有效滚动半径还会变一点，
> 直接拿它算会有同量级的**系统性距离误差**。第 4 节实验 3 用它反推
> `WHEEL_EFFECTIVE_DIAMETER_UM`（固件里的 `WHEEL_DIAMETER_MM` 保持不变）。

**实现注意**：整型除法每拍都会截断，1 拍丢 <1 um 看着无所谓，但 100 Hz × 60 s 会累积到 mm 级。
**做法**：先累加计数，用 `int64` 一次性换算（`Δcounts` 小，成本可忽略）；或保留余数累加器。

### 3.2 麦轮正运动学（车轮位移 → 车体局部位移）

设 `L = a + b`，`a` = 半轴距（前后轮中心距的一半），`b` = 半轮距（左右轮中心距的一半），单位 um。

按 **FL（左前）/ FR（右前）/ RL（左后）/ RR（右后）** 顺序：

```
dx_local_um = ( ds_FL + ds_FR + ds_RL + ds_RR) / 4
dy_local_um = (-ds_FL + ds_FR + ds_RL - ds_RR) / 4
dθ_um_term  = (-ds_FL + ds_FR - ds_RL + ds_RR) / 4      ← 单位 um（弧长）
dθ_mdeg     = dθ_um_term × 57296 / L_um                 ← 57296 = 180000/π
```

**验证矩阵自洽性**（一定要让实现者保留这段推导，否则符号很容易错）：

```
逆解：v_FL = vx - vy - L·ωz     正解反代回去：
      v_FR = vx + vy + L·ωz      和  = 4vx
      v_RL = vx + vy - L·ωz      -FL+FR+RL-RR = 4vy
      v_RR = vx - vy + L·ωz      -FL+FR-RL+RR = 4Lωz
```

⚠ **两个必须实测的符号**（不同资料写法不同，取决于辊子方向）：

1. **A/B/C/D 到 FL/FR/RL/RR 的映射**——由实际装配决定；
2. **`dy` 的符号**——X 型（辊子呈 X）与 O 型布置差一个负号。

**不要照抄，用第 4 节实验 4 标定。**

### 3.3 航向（陀螺仪）

```
heading_mdeg += ωz_mdps × Δt_ms / 1000
```

**定点技巧（避免每拍截断）**：维护一个累加器，单位 `mdps·ms`

```
gyro_accum += ωz_mdps × Δt_ms          /* 100 Hz 时 Δt_ms = 10 */
heading_mdeg += gyro_accum / 1000
gyro_accum   %= 1000
```

**三个必须处理的偏差**：

| 偏差 | 量级 | 处理 |
|---|---|---|
| 零偏（bias） | 已标定时 ±0.5 dps，未标定可到 ±20 dps | 上电静止校准（`MPU6050_CalibrateBias()` 已有）；**跑热后要重校**（温漂最大 0.24 dps/°C） |
| 标度误差（灵敏度） | ±3% | 原地精确转 10 圈标定 `GYRO_SCALE_PERMILLE` 写回参数区 |
| 噪声随机游走 | 与带宽有关 | 校验：静止 60 s 的 `pp` 必须在 1 dps 以内，否则航向不可用 |

### 3.4 位姿更新（车体 → 世界）

用**中点航向**做二阶积分，比用起始航向误差小一个量级：

```
θ_mid_mdeg = heading_prev_mdeg + dθ_mdeg / 2
dx_world_um = ( dx_local_um × cos(θ_mid) - dy_local_um × sin(θ_mid) ) >> 15
dy_world_um = ( dx_local_um × sin(θ_mid) + dy_local_um × cos(θ_mid) ) >> 15
x_um += dx_world_um
y_um += dy_world_um
heading_mdeg += dθ_mdeg          /* 航向优先用陀螺仪，见第 6 节 */
```

### 3.5 定点实现（禁止浮点）

**sin/cos 查表**：

- `SIN_TABLE_Q15[257]`，覆盖 0°..90°，间隔 90/256 = 0.3516°，`+1` 项用于线性插值；
- 表长 514 B（int16），放 flash；
- 索引：`idx_q8 = angle_mdeg × 256 / 90000`（Q8 小数用于插值）；
- 查表 + 线性插值：

```
base = SIN_TABLE_Q15[idx >> 8]
next = SIN_TABLE_Q15[(idx >> 8) + 1]
sin_q15 = base + ((next - base) × (idx & 0xFF)) >> 8
```

- 象限折叠：把 `heading` 归一化到 `[0, 90000)` 并记录象限，按 `sin/cos` 互换与符号翻转取用；
- 插值后误差 < 1 LSB（≈ 3e-5），远小于其他误差源。

**乘法与溢出边界**（给实现者的白名单，超了就是 bug）：

| 表达式 | 最大值 | 说明 |
|---|---|---|
| `ds_um`（单拍） | ~2000 | 4000 counts/s ÷ 100 Hz × 178.5 |
| `ds_um × 32768` | 6.6e7 | int32 安全 |
| `dθ_um_term × 57296` | ~1e8 | int32 安全（term ≤ 2000） |
| `x_um` 累加 | ±2.1e9 | ±2147 m，够用 |

**禁止**：`float` / `double` / `math.h` 的 `sinf`/`cosf`。若确有必要启用 FPU，必须先改 `AGENTS.md` 并说明理由（那是规则允许的唯一路径）。

## 5. 误差分析（这部分决定"能做到多准"）

| 误差源 | 量级 | 对定位的影响 | 缓解 |
|---|---|---|---|
| 编码器量化 | 0.5 count = 89 um | 单次测量噪声，**积分不累积** | 无需处理 |
| CPR / 轮径标度 | 1~3% | 距离 1~3% 同比例 | 实验 2、3 标定 |
| **麦轮打滑** | **横移 10~30%，自转 5~15%** | **主要误差源**，且不可建模 | ①横移比例单独标定 ②避免用横移做精确定位 ③加减速放慢 ④地面别太滑 |
| 轴距/轮距误差 | ±5% 几何 | ωz 标度 1:1 误差 | 实验 5，或直接用陀螺仪定航向（推荐） |
| 四轮直径不一致 | 0.5~2% | **系统性航向漂移**（直行也会偏） | 用陀螺仪纠航向；必要时左右轮分别标定 |
| 陀螺仪零偏漂移 | 校准后 0.5~3 °/min | 航向随时间线性漂 | 周期重校；否则只能用短程 |
| 陀螺仪噪声 | **当前 10~15 dps pp，不可用** | 航向抖动 | 先解决（实验 6） |
| 时间同步 | 编码器 100 Hz / 陀螺仪 ~100 Hz | 相位差 < 5 ms，可忽略 | 位姿更新统一在 10 ms 节拍 |

**诚实结论**：

- **陀螺仪正常、标定到位**的前提下，**短程（2~3 m、几个动作）相对定位**：位置误差 **2~5 cm**、航向误差 **1~3°**。
- **长距离 / 长时间**：误差无界增长，**必须有复位策略**（见第 9 节）。
- 想做到"每次回到原点 ±1 cm"：**光靠编码器 + 陀螺仪不可能**，必须有绝对参考。
- **打滑是天花板**：横移尤其差，这是麦轮方案的固有代价，不是调参能解决的。

## 6. 传感器融合策略

1. **航向以陀螺仪为准**，编码器算出的 ωz 只作交叉校验。
   理由：打滑直接污染编码器的 ωz，而陀螺仪不依赖轮子。
2. **不做互补/卡尔曼来"消漂"**：陀螺仪和编码器**都不是绝对参考**，融合只能降噪，不能消漂。
   想要真值必须引入绝对参考。
3. **位置只用编码器**（陀螺仪不给位移）。
4. **可选增强**（按性价比排序）：
    - 场地标线 / 二维码 / 固定挡块 → 绝对复位（最有效）；
    - `TOF400C` 测墙距做**一维**修正：需要已知墙面位置、且注意它的最小量程约 40 mm 与串扰标定问题（该历史文档已清理）；
    - 起跑前把车手动摆到标记位置并 `ChassisOdom_Reset()`（零成本，务必做）。

### 7.2 数据流与 ISR 分工（硬性，别改）

```
TIM7 ISR (100 Hz, 已有)
  ├─ Encoder_SampleCounts()        ← 唯一计数更新点
  ├─ 算轮速（低通）
  └─ 累加"本轮窗口"的 4 路计数增量 → volatile 快照
     （不做 sin/cos、不读 I2C、不发串口）

EXTI PC3 (MPU 数据就绪)            ← 只置一个 volatile 标志

主循环
  ├─ 看标志 → 读陀螺仪（软件 I2C 是阻塞的，**绝不能在 ISR 里读**）
  ├─ 积分航向（3.3 节）
  ├─ 每 10 ms：取快照 → 麦轮正解算 → 位姿更新（sin/cos 在这里）→ 写 volatile 位姿快照
  └─ 按节拍发遥测（整行一次发出）
```

理由：`AGENTS.md` 第 6 节"控制环 ISR"的五条硬性条件（固定周期、只算不发、只写快照、执行有界、输出限幅）。

```

```

- 上位机单位换算：`x_um/1000 = mm`，`heading_mdeg/1000 = 度`。

### 10.4 对机械/电气设计的反馈（不在定位范畴，但会卡死定位）

1. ❌ **缺少朝下看的摄像头**（现有摄像头前倾 30° 装在升降滑块上）。
   要在圆环上做 <4 mm 放置，必须二选一或兼有：
   ① 一个**垂直向下**的摄像头 + 垂直向下补光（赛题明确允许"仅垂直向下补光"）；
   ② 末端**机械导向**（锥形导套 / 弹性自适应夹指 / 被动对中）。
   **这条不解决，15/10 分档基本拿不到，只能拿 1~3 分。**
2. ⚠ **障碍随机**：400 mm 车道里绕 φ50，横向机动余量只有约 70 mm；
   现有 3×HC-SR04（±45°/0°）够不够要实测，必要时补一个朝前 TOF 或收窄夹角。
3. ✅ **12V 电机供电**（2026-10-07 确认，之前的"2S 7.4V / 空载 205 rpm"记录作废）：
   空载 333 rpm ≈ 1.31 m/s ≈ 7326 counts/s。但闭环输出限幅 600‰
   （`WHEEL_DUTY_LIMIT_PERMILLE`）把可用最高速压到约 **0.78 m/s**，
   算"跑完 2400 mm 场地最快多久"要用这个数，不要用 1.31 m/s。
4. ✅ MPU6050 装在整车几何中心，对航向最有利（离心加速度最小）。

## 11. 风险与已知限制

1. **现在连数据都不全**：只有 A 路编码器有计数，B/C/D 恒 0 → 麦轮正解算缺 3 路，**定位做不了**。
2. **陀螺仪噪声未达标**（`pp` 10~15 dps）→ 航向不可用。这是当前最大的拦路虎。
3. **打滑不可建模**，是麦轮定位的固有天花板。
4. **无浮点限制**带来的常数表与定标成本（已在 3.5 节解决，但实现者要严格遵守）。
5. **时间同步**：陀螺仪走主循环（软件 I2C 阻塞），若主循环有长任务（比如串口大批量发送或 HMI），航向积分会出现抖动。**缓解**：位姿更新用实测 `Δt_ms` 而不是假定 10 ms；并且不要在遥测发送期间做别的事。
6. **CPU/内存**：sin/cos 表 514 B flash；位姿状态 < 64 B RAM；100 Hz 下每次更新约几微秒，占用可忽略。
7. 若后续增加"速度环"（阶段 2），位姿更新要与之共用 10 ms 节拍，避免两个周期互相干扰。

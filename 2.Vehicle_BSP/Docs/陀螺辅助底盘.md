# 陀螺辅助底盘（HWT101）

> **2026-11-09 新增。** HWT101 第一次进生产入口，用来给 `A` / `TASK` 的转身做闭环，
> 并在直行、横移时保持航向。**编译通过，未上板验证。**

## 1. 硬件

| 项 | 值 |
|---|---|
| 模块 | HWT101（维特智能，串口版） |
| 接口 | **USART2**：PA2 = MCU **TX**、PA3 = MCU **RX**（`SERIAL_IMU`） |
| 波特率 | `BOARD_IMU_BAUD` = **115200**（模块出厂默认可能不是这个，见 §6 排查） |
| 协议 | 维特 `0x55` 帧，我们只取 `0x53`（角度）里的 yaw |

接线：模块 **TXD → PA3**（MCU 的 RX）、**RXD → PA2**（MCU 的 TX）、GND 共地、模块供电 5 V（模块自带稳压）。
**TX 必须接 RX，不能 TX 接 TX**——这是"一个字节都收不到"最常见的原因。

## 2. BSP 驱动（`BSP/Src/board_imu.c`）

```c
void     Imu_Poll(void);              /* 主循环每轮调一次：读 USART2、拼帧、校验 */
uint8_t  Imu_Read(ImuSnapshot *out);  /* 原子快照；返回 0 = 还没收到过帧 */
int32_t  Imu_ReadYawMdeg(void);       /* 已减零点、已换向，正值 = 逆时针，0.001 deg */
int32_t  Imu_ReadRateMdps(void);      /* 相邻两帧差分，0.001 deg/s */
uint8_t  Imu_IsFresh(void);           /* 距最后一帧 ≤ IMU_TIMEOUT_MS */
void     Imu_Zero(void);              /* 把当前 yaw 记成 0 */
```

- **拼帧在主循环**，`USART2_IRQHandler` 只往环形缓冲塞字节（符合 AGENTS.md 第 6 节）。
- yaw 不 wrap：连续累积，超过 ±180° 继续加，和 `A`/`TURN_ABS` 的角度语义一致。
- 角速度用相邻帧差分，帧间隔超过 `IMU_MAX_PERIOD_MS` 时不更新（防跳变被放大）。
- 模块自己的 yaw 正方向不一定逆时针：`board_imu.h` 的 **`IMU_YAW_SIGN`** 统一，
  反了改 −1，不用动接线。

### 2.1 把模块出厂默认的 20 Hz 改成 100 Hz

驱动不依赖出数率，但转身精度受它限制：出数率越低，"一次判停"能分辨的角量越大
（20 Hz、600 Hz 慢速时一帧约 0.6°）。容差不能靠放宽来解决——容差一大就会抢在
"过零"之前触发，转身系统性偏短（见 §3 的坑）。所以出数率越高越好。
**在任意串口助手里以模块当前波特率（115200）发三条十六进制命令**：

```
FF AA 69 88 B5     解锁（不发这个，后面两条会被忽略）
FF AA 03 09 00     回传速率 = 100 Hz（寄存器 0x03）
FF AA 00 00 00     保存（不掉电丢失）
```

寄存器 `0x03` 常见映射：`0x06`=10 Hz、`0x07`=20 Hz、`0x08`=50 Hz、**`0x09`=100 Hz**、`0x0A`=200 Hz。
用 WitMotion 上位机更省事：连上后把"回传速率"改成 100 Hz 再点保存。
改完发 `Y`，看 `frames` 的增速和 `age`：100 Hz 下 `age` 应在 0～10 ms 之间。

> 2026-11-09 实板踩过：把第三个字节写成 `06`（10 Hz）时 `age` 会到 95 ms 左右，
> 转身明显变差。**`age` 是判断有没有设对的唯一可靠指标**：10 Hz≈100 ms、20 Hz≈50 ms、
> 100 Hz≤10 ms。另外模块每次更新会发两帧（角度 + 另一种），所以 `raw` 增量 ÷ `frames`
> 增量恒为 22 是正常的，不要拿它当出数率。

## 3. 它改变了什么

只有**拿到新鲜帧**时才生效；模块没接、没上电、波特率不对时，所有行为与以前完全一样。

| 场景 | 没有陀螺（以前） | 有陀螺（现在） |
|---|---|---|
| `A <deg>` 原地转 | 开环：按 `${角度} × L / 轮周长` 算脉冲，走够就停 | 目标 yaw = 当前 yaw + deg，**按 yaw 判到位**提前停；步数仍留着当安全上限 |
| `TASK` 的 `TURN_ABS` | 指令航向递推 + 相对角开环 | **按绝对 yaw 转**（`ChassisMotion_SpinAbs`）：目标 = 站点航向，每站回到同一套绝对朝向，残差不累积；`TASK` 启动/RESET 时自动把当前朝向清零 |
| 直行 / 横移 | 四轮同频，走偏了没人管 | 每 10 ms 按 yaw 误差给左右差速（B/D 加、A/C 减），压住航向漂移 |
| `STOP` / 超时 | 停 | 停（不变） |

转身是**两段速的闭环**：

1. `|误差| > CS_GYRO_TURN_SLOW_ZONE_MDEG`（默认 8°）→ 恒速（原转身转速）；
2. 进入减速区 → 降一次速到 `CS_GYRO_TURN_SLOW_HZ`（默认 600 Hz）；
3. **误差符号一变（刚扫过目标点）就停** —— 这是主判据，剩下误差只有"一帧走过的角量"；
4. 兜底：`|误差| ≤ CS_GYRO_TURN_TOL_MDEG`（**0.3°**）也停；步数上限与超时同样只兜底。

> 容差必须**远小于"一帧走过的角量"**，否则它会抢在过零之前触发，转身就会系统性偏短。
> 2026-11-09 实板踩过：容差设 2.5° 时，每次 `A 90` 都停在 88° 左右（一帧 0.6°，
> 2.5° 在到达前就满足了）。改成 0.3° 后由过零判停，残差压到一帧以内。

只变两次速是有原因的：`Step6_SetHz()` 每次都会停通道、重写 PSC/ARR、再启动，
每 10 ms 改一次频率会让转身一顿一顿。步数与 `CS_GYRO_TURN_TIMEOUT_MS`（15 s）只作兜底：
正常回显 `TURN done (gyro err=… mdeg, rate=…, … ms)`，兜底回显 `TURN capped (…)`。

> **2026-11-09 修正**：第一版把"角速度也要小"当停止条件，但开环转速恒定、没有减速，
> 角速度永远降不下来，结果每次都被步数上限截住（实板日志：`MOVE done 4416 steps`）。
> 现在改成比例减速 + 只看位置误差。
>
> yaw 也改成**连续不 wrap**：模块在 ±180° 处会跳变，驱动按增量累积，转过 360° 就是 360000 mdeg，
> 不会再出现 `+178° → −91°` 这种跳变。

航向保持的修正量 = `Kp × 误差` + `I − Kd × 角速度`，总限幅 `CS_GYRO_HOLD_MAX_PERMILLE`（默认 40% 基速）。
1 Hz 差速约等于 0.02°/s 的转向能力。**横移的偏航扰动是恒定的**，纯 P 一定留固定残差
（实测 1 m 横移残差 0.7°～1.0°），所以加了积分项 `CS_GYRO_HOLD_KI_HZ_PER_DEG_S`。

> **2026-11-09 修正：横移"偏差之后修正不过来"是积分 windup 造成的（改完未编译、未上板）。**
> 旧实现有三个坑，一个 1 m 的横移段就够把积分顶死：
> ① 积分上限直接用了总限幅（40% 基速 ≈ 2170 Hz，配 Kp=150 相当于 14° 的偏置）；
> ② 完全没有抗饱和，误差往同一方向推就一路累到顶；
> ③ 累积门限是 ±5°，而积分顶满后车会被推过头、误差冲出 ±5°，累积条件不成立
> ⇒ **积分再也退不回来，车停在 I/Kp 算出来的固定偏角上**，看起来就是"偏了以后怎么都不回正"。
> 现在：积分上限拆成独立的 `CS_GYRO_HOLD_I_LIMIT_HZ`（250 Hz ≈ 1.7°），
> 只在 |误差| > 死区 时累积，输出顶到限幅时不再累积（条件积分）；
> 并在 `chassis_config.h` 里用 `#error` 保证 **I_LIMIT/Kp 一定大于死区**，
> 否则数学上就会锁死在死区里退不出来。
> 同时把比例项从 `(err/1000)×Kp` 改成 `(err×Kp)/1000`：旧写法把 1 度以内的误差全截成 0，
> **实际死区是 1 度而不是 0.3 度**，最后那 1 度永远修不掉（和实测 0.7~1.0° 的残差对得上）。

> **2026-11-09 修正：TASK 的平移改用绝对航向当目标（改完未编译、未上板）。**
> 旧实现每段平移都在 `wheels_run()` 里把"下命令那一瞬间的 yaw"存成目标，
> 上一段留下的残差就变成下一段的新零点，一条 28 步的路线里连续几段横移会一段段累下去，
> 只有 `TURN_ABS` 能重新拉回绝对朝向。
> 现在 TASK 的 FWD/BACK/LEFT/RIGHT 走 `ChassisMotion_TranslateAbs()`，
> 目标固定为 `task.heading_deg`（TASK 起点 `Imu_Zero()` 那套坐标系），每段都往同一个基准拉；
> 手动 `L/R` 仍是相对模式（在任意朝向下发的命令都合理）。没有陀螺帧时两者行为一致。

平移结束时回显会带上残余航向误差：
`MOVE done 25125 steps 4685 ms (hdg err=-180 mdeg)` —— 这就是判断保持强度够不够的直接依据。

**S 型平滑加减速**：平移从巡航速度的 `CS_MOVE_RAMP_PERMILLE`（2026-11-11 起 **12%**）起，
分 `CS_MOVE_RAMP_UP_STEPS`（12）档、在 `CS_MOVE_RAMP_UP_MS`（350 ms）内爬到全速
（档距按 S 型权重 1,2,3,4,5,6,6,5,4,3,2,1 分配，即**限制加加速度**）；
收尾按**同样档数对称降速**，减速窗口 = `(全速 + 起步速)/2 × 斜坡时长` 对应的步数。
原来只有"40% → 100%"一次跳变、停车也是"全速 → 40% → 0"两次跳变，冲击会被麦轮放大成起步/停车偏航
（实测停车那一下带来约 0.5°）。总步数不变（按每档实际频率积分）。

> **2026-11-11 起步再放缓（用户实测：航向保持已能走直线，只剩起步那一下甩角）。**
> 旧参数 400‰ / 200 ms / 8 档时，**起步第一拍是 0 → 40% 巡航频率的阶跃**
> （横移 0→2173 Hz ≈ 0.16 m/s，直行 0→3802 Hz ≈ 0.28 m/s）——
> 后面那条 S 曲线只决定 40%→100% 怎么爬，管不到这一下，而它正是甩角的来源。
> 现在 120‰ / 350 ms / 12 档，起步阶跃降到 ≈0.05 m/s。
> 另外斜坡时长会**按距离缩短**（`chassis_motion.c` 的 `ramp_ms`，下限 `CS_MOVE_RAMP_MIN_MS`=80 ms）：
> 加速+减速两段最多各占半段行程，否则 150 mm 的对齐段会被两段斜坡吃光、
> 根本到不了巡航速度，还会在斜坡中途被硬停。短段自动变成三角形速度曲线。
> 代价：每个动作的加减速各多 150 ms，整条 TASK 约 +4~6 s。
> ⚠ 这条只管"起步那一刻"。如果改完还剩**方向固定、大小稳定**的小甩角，那是机械不对称，
> 需要在起步窗口里加一个常数差速前馈（这次没做，先看 120‰ 够不够）；
> 继续抬 `Kp` / `KD_LAUNCH` 没用——起步阶段修正量被"当前速度 × 40%"限死。见 §6.2。

## 4. 参数

**BSP（`BSP/Inc/board_imu.h`）**

| 参数 | 默认 | 说明 |
|---|---|---|
| `IMU_TIMEOUT_MS` | 500 | 多久没新帧算掉线 |
| `IMU_YAW_SIGN` | 1 | 模块 yaw 增大不是逆时针时改 −1 |
| `IMU_MAX_PERIOD_MS` | 200 | 帧间隔超过它就不算角速度 |

**App（`App/Inc/chassis_config.h`）**

| 参数 | 默认 | 说明 |
|---|---|---|
| `CS_GYRO_ENABLE` | 1 | 0 = 完全退回开环（对照实验用） |
| `CS_GYRO_TIMEOUT_MS` | 500 | 与 `IMU_TIMEOUT_MS` 对齐 |
| `CS_GYRO_HOLD_UPDATE_MS` | 10 | 航向保持修正周期 |
| `CS_GYRO_HOLD_DEADBAND_MDEG` | 300 | 误差小于 0.3° 不修，避免左右抖 |
| `CS_GYRO_HOLD_KP_HZ_PER_DEG` | 150 | 每 1° 误差加多少 Hz 差速 |
| `CS_GYRO_HOLD_KI_HZ_PER_DEG_S` | 200 | 积分：每 1° 误差每秒累积多少 Hz |
| `CS_GYRO_HOLD_I_LIMIT_HZ` | 250 | 积分**自己**的上限（250/150≈1.7°），必须大于死区，见 `#error` |
| `CS_GYRO_HOLD_KD_HZ_PER_DPS` | 15 | 每 1°/s 角速度加多少 Hz 阻尼 |
| `CS_GYRO_HOLD_LAUNCH_MS` | 300 | 起步后这段时间用更大的阻尼 |
| `CS_GYRO_HOLD_KD_LAUNCH_HZ_PER_DPS` | 40 | 起步阶段的阻尼增益 |
| `CS_GYRO_HOLD_MAX_PERMILLE` | 400 | 修正量最多占基速的比例 |
| `CS_GYRO_HOLD_MIN_STEP_HZ` | 20 | 修正量变化小于它就不重发 |
| `CS_GYRO_STRAFE_BIAS_MDEG` | 0 | 横移蟹行校准偏置（左移 +、右移 −） |
| `CS_TRIM_A_PERMILLE` … `CS_TRIM_D_PERMILLE` | 1000 | 每轴速度微调，配平轮径/装配差异 |
| `CS_GYRO_TURN_TOL_MDEG` | 300 | 兜底容差（正常由"过零"判停；这个值必须远小于一帧角量） |
| `CS_GYRO_TURN_TIMEOUT_MS` | 15000 | 闭环转身超时 |
| `CS_GYRO_TURN_CAP_PERMILLE` | 1500 | 转身步数兜底的倍率。`deg_to_steps()` 等于理论值、余量为 0，打滑就会提前截断；真实失败靠超时兜底 |
| `CS_GYRO_TURN_SLOW_ZONE_MDEG` | 8000 | 进入减速区的误差（8°） |
| `CS_GYRO_TURN_SLOW_HZ` | 600 | 减速区转速；整条转身只变这一次速 |

## 5. 新命令

| 命令 | 作用 |
|---|---|
| `Y` | 打印 yaw、角速度、帧龄、好帧/坏帧数 |
| `Z` | 把当前朝向清零（TASK 启动和 RESET 也会自动清） |
| `X 0` / `X 1` | 关/开平移段的航向保持（现场 A/B 对比用，不影响闭环转身），不带参数则回显当前开关 |

`S` 状态最后多一行：`YAW ok yaw=… mdeg rate=… frames=…`（`none` = 一帧都没收到）。

## 6. 首次上板顺序

1. 只接陀螺、不接电机动力电源。上电发 `Y`：
   - `frames` 一直涨 = 串口通了；
   - `bad` 一直涨而 `frames` 不涨 = 波特率或接线错（TXD/RXD 交叉、模块 9600 没改成 115200）。
2. 手转车体：`Y` 的 yaw 应跟着变。记下**逆时针转时 yaw 变大还是变小**，
   变小就把 `IMU_YAW_SIGN` 改 −1 重编。
3. `Z` 清零 → `E 1` → `A 90`，量实际转角。差得多就调 `CS_SPIN_L_MM`（开环几何）或
   `CS_GYRO_TURN_TOL_MDEG`；方向反了改 `board_step6.c` 的 `STEP6_DIR_INVERT_*`，别在这层翻符号。
4. 跑一段直行（`MALL 300` 落地或 `TASK`），看车头是否比以前稳；抖就加大 `CS_GYRO_HOLD_DEADBAND_MDEG`
   或减小 `CS_GYRO_HOLD_KP_HZ_PER_DEG`，过冲就加大 `CS_GYRO_HOLD_KD_HZ_PER_DPS`。
5. `CS_GYRO_ENABLE 0` 重编一次做对照，确认陀螺确实带来了改善。

### 6.1 `Y` 显示 `frames=0 bad=0` 怎么查

`Y` 现在会打出三行，关键是第二行的 **`raw=`（从 USART2 收到的原始字节数）**：

```text
YAW yaw=0 mdeg rate=0 mdps age=4294967295 ms
    frames=0 bad=0 no fresh frame
    raw=0 drop=0 baud=115200
```

| 现象 | 结论 | 怎么处理 |
|---|---|---|
| `raw` 一直 **0** | 线上一个字节都没有：**接线 / 供电 / 模块没在上报** | 见下面 ①～③ |
| `raw` 在涨、`frames` 一直 0 | 有字节但拼不出 `0x55` 帧：**波特率不对**，或模块不是维特标准帧 | 见 ④～⑤ |
| `raw`、`bad` 一起涨、`frames` 不涨 | 收到 `0x55` 但校验和不对：多半是波特率或干扰 | ④ |
| `frames` 涨但 `Y` 说 `no fresh frame` | 模块停发了，或主循环被别的阻塞卡住 | 看 `age` 是否一直在涨 |

① **TX/RX 必须交叉**：模块 TXD → **PA3**（MCU RX），RXD → **PA2**（MCU TX）。
接成 TX-TX 就是 `raw=0`。

② **共地**：模块 GND 必须和板子 GND 接在一起，只接信号不接地收不到。

③ **供电**：HWT101 用 5 V 或 3.3 V（模块自带稳压），量一下模块 VCC。
指示灯不亮/一直闪不正常＝没上电或模块坏。

④ **波特率**：`raw` 会涨但 `frames=0` 时，先把 `BSP/Inc/board.h` 里的
`BOARD_IMU_BAUD` 临时改成 **9600** 重编试一次——维特不少型号出厂是 9600。
另一种办法是用维特上位机（WitMotion 串口助手）连模块，把波特率改成 115200 并保存。

⑤ **模块不在自动上报模式**：维特的"问答模式"下不会自己发帧。用上位机把它设成
**连续输出 / 100 Hz**，或发解锁帧 `FF AA 69 88 B5` 后设回传速率。

⑥ 顺带看 `drop=`：`Serial_Dropped(SERIAL_IMU)` 涨说明中断里环形缓冲溢出了
（一般是波特率对但主循环被阻塞太久）。`bad` 只统计"收到 0x55 但校验错"的帧，
没有 `0x55` 时它不会涨，所以 `bad=0` 不代表没收到字节——**看 `raw`**。

## 6.2 横移跑偏、而且"偏了回不来"怎么查（2026-11-09）

现场现象：横移起步时车体甩一个角度，之后保持不住、越修越偏。**按这个顺序分**，
前三条是配置/接线，第四条才是代码：

| # | 查什么 | 判据 | 怎么处理 |
|---|---|---|---|
| 1 | yaw 方向对不对 | 手推车逆时针转，`Y` 的 `yaw` 应该**变大** | 变小 ⇒ `IMU_YAW_SIGN` 改 −1 重编。符号反了航向保持是**正反馈**，越修越歪，和这个现象一模一样 |
| 2 | 陀螺出数率 | `Y` 的 `age`：100 Hz ≤10 ms、20 Hz ≈50 ms、10 Hz ≈95 ms | 不是 100 Hz 就先按 §2.1 改；10 Hz 时 P/D 的相位滞后能把任何增益都拖成振荡 |
| 3 | 航向保持有没有在跑 | `X`（不带参数）应回 `hold=1` | 回 0 就发 `X 1` |
| 4 | 控制律本身 | 见下面的 A/B | 已按 `CS_GYRO_HOLD_KI_HZ_PER_DEG_S` 改过，见上面的修正块 |

A/B 判据（每次 `L 1000` 或 `L 900` 落地跑，看回显的 `hdg err=`）：

1. `X 0`（关保持）跑一次 —— 这个数是**纯机械甩尾**，先把它量出来；
2. `X 1` 跑一次 —— 应该明显小于 1；
3. 还不行就把 `CS_GYRO_HOLD_KI_HZ_PER_DEG_S` 改 **0** 重编再跑 ——
   如果 0 反而更好，说明积分还在拖后腿（旧版 walkup 的病根），
   这时要么维持 0（纯 P 留 0.7~1.0° 是可接受的），要么只调 `CS_GYRO_HOLD_I_LIMIT_HZ`；
4. 到点瞬间的 `hdg err` 由**停车滑移**贡献一部分，改不了多少——要看的是
   下一段起步后有没有被拉回来，而不是这一段的收尾数字。

## 7. 已知限制

- **位移仍然是开环**：陀螺只管"朝哪"，不管"走了多远"。里程还得靠编码器（本板没有）。
- 航向保持只修正偏航，**横向滑移修不了**。
- 每当修正生效时会调用 `Step6_SetHz()` 重配 PSC/ARR，通道会停几十微秒；
  6 kHz 下大约丢 0 个脉冲，但 10 ms 一次的修正频率别调太密（`CS_GYRO_HOLD_UPDATE_MS` ≥ 5 ms）。
- 帧率取决于模块自身配置（HWT101 默认 100 Hz 左右）。`Imu_Poll()` 每轮把串口读空，
  主循环再慢也不会丢帧（环形缓冲 64 字节，100 Hz × 11 字节够用）。
- 陀螺的 yaw 会缓慢漂移（没有磁力计校正），长路线建议在每个站点 `Z` 或 `RESET` 重定零。

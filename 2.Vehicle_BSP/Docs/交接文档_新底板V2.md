# 交接文档：新底板（V2，六轴步进）

> 2026-11-03 编写。**记录的是已经打样焊接的这块板**，不是当初的设计方案。
> 两者有差异的地方在 §6 单独列出。
> 事实来源：嘉立创EDA 工程 `gshwww5/STEP` / 板 `电控板` 的网表（2026-10-30 抓取），
> 与 `BSP/Inc/pins/stepper6.h` 交叉核对过。

---

## 1. 这块板是什么

核心板 **FK407M3-VET6**（STM32F407VET6，LQFP100）插在新画的底板上。

和上一代最大的区别：**底盘四个轮子从直流电机换成了张大头闭环伺服（STEP/DIR），
四路编码器全部取消**。所以这块板是纯开环的——没有轮速反馈，位置只能靠步数估算。

| 项目 | 数量 | 说明 |
|---|---|---|
| 底盘轮 | 4 | 张大头闭环伺服，STEP/DIR |
| 旋转台 | 1 | 同上 |
| 升降台 | 1 | 同上 |
| 舵机 | 2 | 50 Hz PWM（夹爪 + 载物台） |
| 串口 | 5 | 调试 / 陀螺 / 树莓派 / 串口屏 / 蓝牙 |
| 编码器 | 0 | **已取消** |
| IMU / TOF | 0 | **这块板上没画** |

## 2. MCU 引脚全表（as-built）

「网络名」是原理图里的网络标号，排障时以此为准。

### 2.1 步进六轴

| 轴 | 网络 | STEP | 定时器 | 网络 | DIR |
|---|---|---|---|---|---|
| A | STEP1 | **PE9** | TIM1_CH1 | DIR1 | **PE7** |
| B | STEP2 | **PE6** | TIM9_CH2 | DIR2 | **PE8** |
| C | STEP3 | **PA0** | TIM2_CH1 | DIR3 | **PE10** |
| D | STEP4 | **PB0** | TIM3_CH3 | DIR4 | **PE12** |
| 旋转 | STEP_turn | **PD12** | TIM4_CH1 | DIR_turn | **PE13** |
| 升降 | STEP_up_down | **PA6** | TIM13_CH1 | DIR_up_down | **PE14** |

- 六个轴**各占一个独立定时器**。这不是浪费，是必须的：同一定时器的所有通道共用 ARR，
  只能输出一种频率，而麦轮转向/横移时四轮速度各不相同。
- 六路 DIR 全部在 GPIOE（PE7/8/10/12/13/14），可以一次 `GPIOE->ODR` 改完。
- A/B/C/D 是原理图网络名，**前后左右的物理对应关系还没在整车上确认过**。

### 2.2 使能

| 网络 | 引脚 | 控制谁 |
|---|---|---|
| EN | **PD3** | A/B/C/D 四路并在一起 |
| EN1 | **PC8** | 旋转 |
| EN2 | **PC9** | 升降 |

低有效。底盘四路共用一个使能，**不能单独禁某一个轮子**。

### 2.3 舵机

| 网络 | 引脚 | 定时器 | 接谁 |
|---|---|---|---|
| SERVO_J_PWM | **PB14** | TIM12_CH1 | 夹爪 |
| SERVO_X_PWM | **PB15** | TIM12_CH2 | 载物台 |

两路共用一个定时器，天然同频。⚠ **信号线上没有串阻、没有 TVS**（见 §6）。

### 2.4 串口

| 网络 | 引脚 | 外设 | 接谁 |
|---|---|---|---|
| — | PA9 / PA10 | USART1 | 调试（核心板 USB） |
| hw_TX / hw_RX | **PA2 / PA3** | USART2 | HWT101 陀螺（`hw_TX`→模块 RX，`hw_RX`→模块 TX） |
| RPI_RX / RPI_TX | PC10 / PC11 | USART3 | 树莓派 |
| HMI_TX / HMI_RX | PC6 / PC7 | USART6 | 串口屏 TJC |
| SPARE_TX / SPARE_RX | **PC12 / PD2** | **UART5** | 蓝牙（4P 座） |

- PA2/PA3 **不 5V 容忍**，只能接 3.3V 逻辑。
- 蓝牙座是 SPARE 那个 4P：1=PC12(TX)、2=PD2(RX)、3=GND、4=5V。
  接 HC-05 要交叉：模块 TXD→PD2，RXD→PC12。

### 2.5 其它

| 功能 | 引脚 | 备注 |
|---|---|---|
| 按键 | **PB3** | 10k 上拉到 3V3_IO + 100nF 到地 |
| 板载 LED | PC0 | 核心板自带，低电平点亮 |

### 2.6 在原理图上但什么都没接的

| 网络 | 引脚 | 说明 |
|---|---|---|
| INT1 | PC3 | 只有一个端点，悬空 |
| INT2 | PC2 | 同上 |
| `$1N217` | PD13 | 单端网络，残留 |

这三个在 DRC 里会被报"单端网络"。布线时留着无害，但**别往上面接东西**——真接上去
反而会以为是设计好的。

### 2.7 空闲引脚

PA1、PA4、PA5、PA7、PA8、PA11、PA12、PA13、PA14、PA15、PB1、PB2(BOOT1)、PB4、
PB5、PB6、PB7、PB8、PB9、PB10、PB11、PB12、PB13、PC1、PC4、PC5、PD4、PD5、PD6、PD7、
PD8、PD9、PD10、PD11、PD13、PD14、PD15、PE0~PE5、PE11、PE15。

其中 PD6/PD7/PD8/PD9 适合接限位（普通 GPIO + EXTI）；PA4/PA5 是 ADC1_IN4/IN5；
PB6/PB7 是 I2C1 的默认引脚。PC0/PC1 被核心板的 LED 和按键占用，底板别用。

## 3. 连接器

| 位号 | 型号 | 引脚定义 |
|---|---|---|
| CN1 | KF2EDGV-3.81-6P | 1=逻辑5V 入、2=GND、3=3.3V 入、4=GND、5=舵机5V 入、6=GND |
| U12 | XT30 2×2 | 12V 输入（1=GND，2=经 `12v` 开关） |
| PING | HX2.54-4P | 串口屏：1=5V、2=GND、3=PC7(HMI_RX)、4=PC6(HMI_TX) |
| PI | HX2.54-4P | 树莓派：1=PC10(RPI_RX)、2=PC11(RPI_TX)、3=GND、4=空 |
| SPARE | HX2.54-4P | 蓝牙：1=PC12、2=PD2、3=GND、4=5V |
| 载物台 / 夹爪 | XH2.54-3P | 1=GND、2=VCC(5V_SERVO)、3=信号 |
| 按钮接入 | HX2.54-2P | 1=KEY(PB3)、2=GND |
| 补光灯 | XH2.54-2P | 1=GND、2=12V（**常亮，没有控制脚**） |
| A/B/C/D/旋转/升降 | 张大头闭环伺服 | 见 §4 |

树莓派只有串口和地过去，**5V 要单独供**（PI 的 4 脚没接电源）。

## 4. 驱动器接法（张大头闭环伺服，6 位）

| 脚 | 含义 | 接到 |
|---|---|---|
| 1 | 12V | `12V` 母线 |
| 2 | GND | `GND` |
| 3 | COM | `GND` ← **必须接，光耦的参考地** |
| 4 | EN | 底盘四路并到 PD3；旋转 PC8；升降 PC9 |
| 5 | STEP | 见 §2.1 |
| 6 | DIR | 见 §2.1 |

COM 接 GND 是这块板的关键接线：3.3V 信号直接驱动光耦，MCU 拉高时灌电流。
六路同时翻转的瞬态电流不小，**如果出现"某一轴偶尔丢步/不转"，先怀疑这里**，
必要时加一级 74HC245 缓冲，不要先去改代码。

## 5. 电源

```
XT30 12V ──[12v 开关]──┬── 六个驱动器的 pin1（就近无独立电容）
                       └── C4 470µF + C8 100µF + 0.1µF×2 ── 补光灯

CN1-1 5V ──[逻辑5V 开关]──┬── 核心板 5V（M1-1/2）
                          ├── 串口屏 PING-1
                          ├── SPARE-4（蓝牙）
                          └── C6 100µF + 0.1µF×2

CN1-3 3.3V ──[3.3 开关]──┬── HWT101 VCC
                          ├── 按键上拉 U13 10k
                          └── 10µF + 0.1µF×2

CN1-5 舵机5V ──[舵机5V 开关]──┬── 两路舵机 VCC
                               └── C1 470µF + C5 470µF + 0.1µF×2
```

**三个要注意的地方：**

1. **核心板的 5V 和 CN1 的外部 5V 是直连的**，中间只有一个开关。插着 USB 调试同时
   外部又供 5V，两边会打架（电流倒灌进电脑 USB 口）。要么只留一个来源，要么加防倒灌。
2. **12V 入口没有保险丝、没有反接保护**。
3. **每个驱动器脚下没有就近电容**，六路共用 C4/C8 两颗。大电流启动时压降会明显。

### 5.1 2026-11-06 事故记录：换 24V 电池后核心板 + 蓝牙同时烧毁

- **事件**：换 24V 电池上电后，STM32 核心板与 HC-05（两者都在 CN1 的 5V 轨上）同时烧毁；
  事后量 CN1 的 5V 输入"还是正常的 5V"。烧毁发生在**瞬时过压事件**里，稳态读数不能排除事发瞬间过压。
- **板级事实**：这块板上**没有任何 DC-DC**，5V / 3.3V / 舵机 5V 全是 CN1 外部输入——
  **换电池电压时，这三路的外部来源必须一起重新选型**，不能只换电池。
- **疑因**（按概率排，待对那颗降压模块解剖确认）：
  1. 给 CN1 供 5V 的 buck 是 12V 平台（输入上限常见 ≤26V），24V 满电 25.2V +
     驱动器开关尖峰 → buck 击穿**输入直通输出**，24V 瞬灌 5V 轨；
  2. 24V 曾短暂进过 CN1（插座/端子接错）；
  3. XT30 热插拔尖峰经共地窜入逻辑域（概率最低）。
- **若保留 24V 的前提**：每路 buck 输入范围 ≥ 32V（留尖峰余量）；5V/3.3V 各加 5.1V 级
  TVS + 自恢复保险丝；电池干路加保险丝 + 防反（本板没有）；先核实 X42S 支持 24V 母线；
  **补光灯是按 12V 设计的常亮支路，24V 下先断开**。否则换回 12V 最省事。
- **复测规矩**：换新核心板/HC-05 后，外设先全断，空板确认 LED 心跳，再逐个挂载验证；
  一次只允许一个 5V 源，USB 与 CN1 5V 不同时上（见上面第 1 条）。

## 6. 打了但没做的（和原方案的差异）

原方案在 `Docs/新板引脚分配_6路步进.md`，下面是**这版板子实际没实现**的部分：

| 项目 | 方案 | 实际 |
|---|---|---|
| M4 STEP | PB4 | **改成了 PB0**（PB4 是 JTAG 的 NJTRST，复位带上拉，会让 D 轴蹭一步） |
| 机械臂独立使能 | PE15 | **没有**，只有 PC8/PC9 分旋转/升降 |
| 步进总故障 | PD4 | **没有**，六路 nFAULT 没接 |
| I2C（MPU6050 / TOF） | PB6/PB7 + 4.7k 上拉 | **整条删了**，一个器件都没画 |
| TOF SHUT | PD5 | **没有** |
| 限位 / 原点 | PD8/PD9 | **没有** |
| 电池电压 / 电流采样 | PA4/PA5 | **没有** |
| 舵机串阻 220Ω + TVS | 有 | **没有，信号线直连** |
| 12V 保险丝 / 反接保护 | 有 | **没有** |

**舵机那一条要特别提醒**：老板的 PE5 就是被舵机信号这一路打坏的（输出驱动失效，
引脚恒为浮空 1.68V）。这块板子把舵机改到了 PB14/PB15，但**没有做任何保护**，
同样的失效模式完全可能再来一次。

### 7.2 关键约束：不能走 `Board_Init()`

`Board_Init()` 会把 TIM2/TIM3/TIM4 配成**编码器模式**，而这三个定时器在这块板上是
C、D、旋转三个轴的 STEP 输出。直接调它 = 三个轮子拿不到脉冲，现象是"A/B 转、C/D 死"。

所以 `main.c` 里 `CHASSIS_STEP_TEST` 单独走 `Board_InitStep6()`，只做 GPIO + 六个定时器 + 串口。

### 7.3 还是老硬件逻辑、在这块板上跑不了的

- `board_motion.c`：AT8236 四路 PWM、DRV8825 两轴、编码器初始化——**全部对应老板**。
  **例外（2026-11-09）**：两路舵机已抽成独立的 `Servo_Init()`，按 V2 配 PB14/PB15 + TIM12，
  `Board_Init()` 和 `Board_InitStep6()` 都会调它——所以新板生产入口能单独初始化舵机，
  但需要显式调 `Servo_SetPulseUs()` / `Servo2_SetPulseUs()` 才出脉冲（目前还没有舵机命令）。
  其余 AT8236/DRV8825/编码器初始化仍留在 `Board_MotionInit()` 里，所以在 V2 板上
  **整条 `Board_Init()` 还是不能用**。
- `board_encoder.c` / `board_wheel.c`：四路编码器 + 轮速闭环，这块板没有编码器。
- `board_comm.c`：**2026-11-03 已改完**。`SERIAL_BT` → UART5（PC12/PD2），
  新增 `SERIAL_IMU` → USART2（PA2/PA3，HWT101），`PORT_COUNT` 由 4 变 5，
  `stm32f4xx_it.c` 补回 `USART2_IRQHandler`。**当日已随全量重建编译通过**
  （5 个 Target 均 0 Error / 3 条 HAL 自带警告）。
  注意 `wheel_smoke.c` 里 `hwt_poll()` 读的口已经从 `SERIAL_BT` 改成 `SERIAL_IMU`，
  否则陀螺会去读蓝牙的字节。
- `WHEEL` / `RIG` / `HMI` 三个 Target：都依赖老硬件，**在新板上不能直接用**。

### 7.4 CHASSIS_STEP 命令（USART1 或 蓝牙 UART5，115200）

> 2026-11-03 起**两个命令口都收**（USART1 有线 + `SERIAL_BT` 蓝牙），各自独立拼帧，
> 回复走命令来的那个口。此前只读 USART1，蓝牙上的命令全部被忽略——
> 所以"蓝牙配对了但发指令没反应"先确认烧的是这个版本之后的固件。

```
E 1                  使能
M a 300              A 轮 30%
MALL 300             四轮同速
J a -200             点动 200 步（负数反向）
D a 0|1              改单轮方向
F 8000               设满速频率
STOP                 全停
? / P / H             状态 / 引脚表 / 命令表
```

上电不发脉冲、四路失能。8000 Hz ≈ 2.5 转/秒 ≈ 0.59 m/s（16 细分、200 步/转、轮径 75 mm）。

## 8. 接下来该做的（按优先级）

1. **示波器验脉冲**：不接电机，`E 1` 后 `M a 300`，量 PE9 应是 2400 Hz、50% 方波。
   这一步把"固件没出脉冲"和"驱动器/电机有问题"分开，别跳过。
2. **四轮方向确认**：逐个 `J` 一次，记下哪边是"车头向前"；`MALL 300` 看整车走不走直线。
   不同向说明某一路 DIR 反了，改接线或改 `board_step6.c` 里的方向表。
3. ~~补蓝牙~~ **已完成（2026-11-03，代码审查 + 编译通过，未上板）**：`SERIAL_BT` 挪到 UART5（PC12/PD2），
   USART2 单独留给陀螺（新增 `SERIAL_IMU`）。上板时要验的是：HC-05 收发交叉、
   波特率与模块 `AT+UART` 一致、以及陀螺帧还能正常收到。
4. **补限位**：升降/旋转没有原点，上电位置不确定，第一次动作容易顶死。PD8/PD9 空着。
5. **补保护**：舵机串阻 + TVS、12V 保险丝、5V 防倒灌。
6. **决定还要不要视觉/IMU**：这块板上没有 I2C 器件位，要加只能飞线或改板。

## 9. 怎么重新核对接线

不要凭这份文档（或任何文档）直接改硬件。抓一次现场网表最快：

```
双击 D:\Study\Next\32\dump-run.bat
```

会在工程目录生成 `easyeda-dump.json` 和 `netlist.txt`，后者一行一个网络，
搜 `M1-` 就能看到 MCU 每个脚挂在哪个网络上。

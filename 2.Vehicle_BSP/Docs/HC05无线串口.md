# HC-05 无线串口（UART5 / PC12/PD2）

本文说明**两块 HC-05 对接**的配置方法，以及接到 STM32F407 车板后的固件用法。
目标链路：**车上有线接到电脑，用来在 VOFA+ 里看波形调闭环**。
树莓派串口（USART3 / PC10/PC11）和串口屏（USART6 / PC6/PC7）**保持原样不动**。

```
STM32F407 车板 ──UART5 PC12/PD2── HC-05(主机) ~~~空口~~~ HC-05(从机) ──USB-TTL── PC(VOFA+)
```

---

## 1. 为什么是 UART5 / PC12/PD2

| 串口 | 引脚 | 现状 | 能否给 HC-05 |
|---|---|---|---|
| USART1 | PA9/PA10 | 调试口，115200 | 会失去有线调试 |
| USART2 | PA2/PA3 | **新底板 V2 起给 HWT101 陀螺**（`hw_TX`→PA2、`hw_RX`→PA3） | ❌ 要留给陀螺 |
| UART5 | **PC12/PD2** | **2026-11-03 起给蓝牙** | ✅ 本方案 |
| USART3 | PC10/PC11 | 树莓派，115200 | 要留给树莓派 |
| USART6 | PC6/PC7 | 串口屏，115200 | 要留给屏 |

老板上 USART2 既当蓝牙又让陀螺抢，两者共用不了；新底板 V2 把蓝牙挪到 UART5（PC12=TX / PD2=RX，AF8，SPARE 4P 座），USART2 干净留给陀螺，两者各占一路、互不占用（见 `Docs/交接文档_新底板V2.md`）。接线时注意**交叉**：PC12（MCU TX）接模块 RXD、PD2（MCU RX）接模块 TXD。

⚠ PC12/PD2 不是 5V 容忍，只能接 3.3V 逻辑。

---

## 2. 角色分配：车上的做主机

HC-05 的 `ROLE` 是模块自己的属性：主机（`ROLE=1`）主动去连，从机（`ROLE=0`）等着被连。

| 位置 | 角色 | 理由 |
|---|---|---|
| 车上 HC-05 | **主机**（`ROLE=1` + `CMODE=0` + `BIND` PC 侧地址） | 上电后**自动重连**绑定的从机，不用在电脑上点"连接" |
| PC 侧 HC-05 | **从机**（`ROLE=0` + `CMODE=1`） | 插在 USB-TTL 上，只负责等连接 |

> 反过来也能用（PC 侧做主机），但那样每次都要在电脑上点一次连接，车一动就重连不上。
> 手机也能直接连从机模块（用「Serial Bluetooth Terminal」这类经典蓝牙 SPP 的 App），iOS 不支持。

**先确认模块不是 HC-06**：HC-06 只能做从机，发 `AT+ROLE?` 会回 `ERROR`。要看型号就发 `AT+VERSION?` / `AT+NAME?`。

## 3. 进 AT 模式（配置阶段）

### 3.1 接线：先接 USB-TTL，不要接车板

| USB-TTL | HC-05 | 说明 |
|---|---|---|
| 5V（或 3.3V） | VCC | 模块板载 LDO，VCC 3.6~6V |
| GND | GND | 共地 |
| RXD | TXD | 交叉 |
| TXD | RXD | 交叉 |
| 3.3V（或按住模块按键） | **EN / KEY** | **上电前**就要为高，否则进不去 AT 模式 |

上电后 **LED 慢闪（约 2 秒一次）= AT 模式**。
数据模式下 LED 是：快闪 = 未连接，双闪 = 已连接。

### 3.2 串口助手设置

| 项 | 值 |
|---|---|
| 波特率 | **先试 38400**，不回 `OK` 再试 9600 / 115200 |
| 数据位 / 停止位 / 校验 | 8 / 1 / None |
| 换行 | **Both NL & CR**（`\r\n`） |

AT 模式用的就是模块**当前的数据波特率**，所以模块被人改过的话，AT 也要用改后的值。
**判断波特率是否正确的唯一标准：发 `AT` 能收到 `OK`。**

### 3.3 别把 KEY 接到 STM32 的 GPIO

想用软件进 AT 模式是行不通的：KEY 必须在**模块上电的那一瞬间**为高，而那时 STM32 还没跑起来。
配置阶段用跳线帽 / 模块自带按键，配完把 KEY 拔掉（悬空或接地）即进入数据模式。

## 4. AT 命令

```text
AT                     → OK            （通不通就看这一条）
AT+VERSION?            → +VERSION:2.0-20100601
AT+ORGL                → OK            （可选：恢复出厂，排除历史改动）
AT+NAME? / AT+PSWD? / AT+UART? / AT+ROLE? / AT+CMODE? / AT+ADDR?
```

**PC 侧模块（从机）**

```text
AT+ROLE=0
AT+CMODE=1                 // 任意地址都可连
AT+PSWD="1234"             // 两边必须一致
AT+UART=115200,0,0         // 与 BOARD_BT_BAUD 对齐（1 停止位、无校验）
AT+NAME=PC_SLAVE
AT+RESET                   // 改完必须复位才生效
AT+ADDR?                   // 记下这个地址，形如 +ADDR:98d3:31:10e2a5
```

**车上模块（主机）**

```text
AT+ROLE=1
AT+CMODE=0                 // 只连绑定地址（=1 会连上任意已配对设备，不推荐）
AT+BIND=98d3,31,10e2a5     // ⚠ 地址里的冒号要改成逗号
AT+PSWD="1234"
AT+UART=115200,0,0
AT+NAME=CAR_MASTER
AT+RESET
```

要点：

1. `AT+BIND` 的地址格式是**逗号**分隔，而 `AT+ADDR?` 输出是**冒号**分隔，必须手工转换。
2. 改了 `ROLE` / `CMODE` / `BIND` / `UART` 之后**一定要 `AT+RESET`**。
3. 改完 `AT+UART`，串口助手要立刻切到新波特率，否则后面全是乱码。
4. 两块模块的**串口波特率各自独立**（各自跟自己的 MCU / USB-TTL 说话），空口速率是另一回事；两边都设成 115200 只是为了好记。
5. 配对成功后两边 LED 都变**双闪**；主机上电后几秒内自动连上属正常。

## 4.1 解除地址绑定

HC-05 里有**三样东西**容易被笼统叫成"绑定"，要分清才能对症下药：

| 概念 | 命令 | 作用 |
|---|---|---|
| **地址绑定** | `AT+BIND=` | 只记一个对端地址，**只有 `CMODE=0` 时才生效** |
| **连接模式** | `AT+CMODE=` | `1` = 连任意设备（BIND 值留着也不起作用）；`0` = 只连 BIND 的地址 |
| **配对记录表** | `AT+RMAAD` | 模块记着"以前配对过谁"，`CMODE=1` 时上电会**优先回连旧设备**，只改 CMODE 是清不掉的 |

### 先看一眼当前状态

```text
AT+BIND?      → +BIND:98d3:31:10e2a5   （或 +BIND:0:0:0 表示没绑）
AT+CMODE?     → +CMODE:0
AT+ADCN?      → +ADCN:1                （配对记录条数）
AT+ROLE?      → +ROLE:1
```

### 解除（按需要选，最后都要 `AT+RESET`）

```text
AT+CMODE=1                 // ① 最常用：让绑定失效，从此连谁都行
AT+BIND=0000,0,0000        // ② 真正清掉 BIND 记录（有的固件回 ERROR，见下）
AT+RMAAD                   // ③ 清空配对记录表，否则上电还会优先回连旧设备
AT+RESET
```

要点：

- **只想"别死绑那一个地址"，发 `AT+CMODE=1` 就够了**，BIND 值留着不生效，不必强清。
- ② 的 `AT+BIND=0000,0,0000` 在部分固件上回 `ERROR`，那就改用 `AT+BIND=0`；
  两个都不行就只剩 `AT+ORGL`（见下）。地址格式永远是**逗号**分隔。
- **⚠ `AT+ORGL` 的副作用很大**：它把 BIND 和配对表一起清掉，但也把
  `UART` 复位成 **9600**、`NAME` 变回 `HC-05`、`ROLE` 变回从机、`PSWD` 变回 `1234`。
  本工程用的是 115200，所以 `AT+ORGL` 之后**必须重新发 `AT+UART=115200,0,0`**，
  否则串口助手在 115200 上就再也收不到 `OK` 了（切回 9600 才能救回来）。
- 从机侧的 `BIND` 是"回连主机"用的，**同样的一套命令**在从机上清一遍。
- 清完可以用 `AT+INQ` 搜一下周围设备（列出 `+INQ:地址,类型,RSSI`），确认能重新发现对端，
  再用 `AT+PAIR=98d3,31,10e2a5,10` + `AT+LINK=98d3,31,10e2a5` 手工连一次试试。

## 5. 接到车板

| HC-05 | STM32F407 | 说明 |
|---|---|---|
| VCC | 5V 或 3.3V | 模块板载 LDO；SPARE 座的 4 脚是 5V |
| GND | GND | **必须共地** |
| TXD | **PD2**（`BT_RX`） | 交叉 |
| RXD | **PC12**（`BT_TX`） | 交叉，只接 3.3V 逻辑 |
| EN / KEY | 悬空或接地 | 数据模式 |

供电提醒：HC-05 建链瞬间电流会冲到 40~100 mA，如果模块反复重启，在模块 VCC/GND 之间并一个 100 µF 电容。

固件侧已经做成第四路串口，**不需要改任何 BSP 代码**：

```c
#include "board.h"

/* 发（阻塞式；115200 下每字节约 87 us，脉冲期间不要调，见 AGENTS.md 第 6 节） */
Serial_Write(SERIAL_BT, buf, len, 20U);

/* 收：中断只入队，拼帧放主循环 */
int byte = Serial_ReadByte(SERIAL_BT);
```

| 层 | 位置 |
|---|---|
| 引脚宏 | `BSP/Inc/pins/bt_uart.h` |
| 串口枚举 / 波特率 | `BSP/Inc/board.h`（`SERIAL_BT`、`BOARD_BT_BAUD`） |
| 初始化 / 环形缓冲 | `BSP/Src/board_comm.c` |
| 中断入口 | `Core/Src/stm32f4xx_it.c` 的 `UART5_IRQHandler()` |
| 引脚表 | `Docs/PINMAP.md` |

## 6. 无线调参怎么用

原 `Tests/Src/encoder_smoke.c`（`ENCODER` Target）的参数区里有两个开关
（**该 Target 已于 2026-10-27 删除**，等价的遥测/文本端口开关见 `Tests/Src/wheel_smoke.c` 参数区）：

```c
#define ENCODER_SMOKE_TELEMETRY_PORT   SERIAL_DEBUG   /* 改成 SERIAL_BT 就走蓝牙 */
#define ENCODER_SMOKE_TEXT_PORT        SERIAL_DEBUG   /* 人读文本始终留在有线 USART1 */
```

- **数字遥测（FireWater）**走 `TELEMETRY_PORT`，改成 `SERIAL_BT` 后 PC 通过蓝牙收波形；
- **人读文本**（开机信息、错误、`S` 状态行）走 `TEXT_PORT`，留在有线的 USART1 —— 同一条 UART 上遥测流必须只有数字行（`AGENTS.md` 第 6 节）；
- **命令两个口都收**，所以接蓝牙时 `M a 300` / `STOP` / `T 0` 直接从 VOFA+ 的发送框发就行。

带宽预算（115200 8N1 ≈ 11.5 kB/s）：

| 项目 | 数值 |
|---|---|
| 9 通道一行 | 约 50 字节 |
| 50 Hz | 2.5 kB/s（占 115200 的 22%） |
| HC-05 SPP 实测吞吐 | 约 20~50 kB/s（空口 1 Mbps 级，受模块缓冲限制） |

结论：50 Hz 遥测绰绰有余，速度快了提到 230400 也带得动（两边模块和 `BOARD_BT_BAUD` 一起改）。
注意蓝牙**单向延迟约 10~30 ms**，看波形调参没问题，但别把它当成实时控制回路的一部分。

## 7. 排查表

| 现象 | 原因 |
|---|---|
| 发 `AT` 没有任何回显 | 波特率不对（试 38400 / 9600 / 115200）；换行符不对；KEY 不是上电前拉高的 |
| 返回 `ERROR` | 命令拼错；或是 HC-06 不支持该命令（如 `AT+ROLE`） |
| 一直回 `ERROR` 且改不了 | 用 `AT+ORGL` 恢复出厂再来 |
| 改完参数就乱码 | `AT+UART` 已生效，串口助手要切到新波特率 |
| 主机连不上从机 | 从机没上电 / `AT+BIND` 地址格式写成冒号 / 两边 `PSWD` 不一致 / 没 `AT+RESET` |
| 模块反复重启 | 供电电流不足，加 100 µF 电容或换 5V 供电 |
| 车板发数据 PC 收不到 | 收发没交叉；没有共地；`BOARD_BT_BAUD` 与模块 `AT+UART` 不一致；`Serial_Dropped(SERIAL_BT)` 在涨说明主循环没及时取走 |
| 蓝牙通、有线调试口没输出 | 正常：文本口是 `ENCODER_SMOKE_TEXT_PORT`，检查它是不是被改成了 `SERIAL_BT`（那样两个口就重了） |

- **编译**：蓝牙从 USART2 挪到 UART5 后**尚未重新编译**（代码改动：`pins/bt_uart.h` 引脚宏、`board_comm.c` 的 `ports[]`/时钟/`uart_start`/NVIC、`stm32f4xx_it.c` 的 `USART2_IRQHandler`→`UART5_IRQHandler`）。
- **实板**：**尚未上板验证**。需要确认的项（新板走 `CHASSIS_STEP` 台架，命令口在 USART1）：
  1. 两块 HC-05 能配对（LED 双闪）；
  2. 蓝牙接到 SPARE 座（PC12/PD2）后，PC 侧能收到车板通过 `SERIAL_BT` 发出的**数字行**（文本行在有线 USART1）；
  3. 从 VOFA+ 通过蓝牙发命令能控制轴动作；
  4. 断线重连：从机上电顺序颠倒时，主机能在几秒内自己重连上。

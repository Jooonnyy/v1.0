（624 行，作者自注 2025/8/14 v1.0）与 `Readme.txt`。

与 `2025智能物流搬运_PCB_XAUT_20261019.eprj2` 本次不看。

## 1. 一句话结论

他们的视觉**没有坐标系，只输出目标在当前帧里的像素坐标**，由下位机闭环到"误差归零"。
这既是这套方案最大的短板（换相机、换高度、换视角全废），也是它对我们最有价值的地方——
**它证明了一条不需要任何标定就能先跑起来的路径**。

上一轮只看搜索引擎摘要时，我判断"色环算法值得抄"。看到代码后需要修正：
预处理链的思路确实值得拿，但代码本身有三处硬伤（CLAHE 算完没用、圆数必须恰好 3 个、
半径硬编码），直接复制会得到一个更难调的东西。真正值得优先拿的是第 3 节的"三点判据"。

| 项 | 内容 |

| 标定 | **无**。没有内参、没有畸变校正、没有平面外参、没有颜色标定工具 |

## 4. 可以拿的三样

### 4.1 三点判据（最值得拿）

`color_circle_position()` 返回三个色环中心后，`unit==3` 分支（L397-405）发的是：

- `send[2..5]` = **中间**那个圆的像素 `x, y` → 平移误差
- `send[6..7]` = `qy1 - qy3`（左圆 y 减右圆 y）→ **航向误差**

这个组合的好处是：航向用两点的**差分**，目标整体平移不会污染姿态估计；而平移直接
取中间圆的像素位置，也不需要知道毫米。**两个量都不依赖标定**。

对我们的意义：现有 `$V` 帧的 `yaw_mdeg` 是主轴方向反投算出来的，一旦平面外参没标好就
全是错的。可以把"左右目标 y 差（像素）"作为**独立的调试量**并行输出，用于在没有标定时
先把闭环跑起来。等标定做完再切回 `yaw_mdeg`，两者还能互相校验。
具体实现建议放在 `vision_node.py` 里做一列可选字段，不改 `$V` 帧——先用 `--preview`
叠字和 stdout 看，进固件是后一步。

### 4.2 色环预处理链（要改，不能抄）

他们的链条是：

```
腐蚀 → 膨胀填洞 → 灰度 → CLAHE → 形态学梯度 → 高斯 → ×4 提对比度
→ 高斯 → 二值化(70) → 高斯 → HoughCircles(HOUGH_GRADIENT_ALT, 1.5, 50, 100, 0.95, r=15..50)
```

方向是对的：**不靠颜色阈值，靠环形几何特征**，这正是强光和阴影下比 HSV 稳的原因。
但这段代码不能直接搬，三处硬伤：

1. **CLAHE 算完没用**（L194-195）。`clahed = clahe.apply(gray_img)` 之后，L199 的
   `gradient` 用的是原始 `gray_img`，`clahed` 是个死变量。等于抗光照的那一步根本没生效。
2. **圆数必须恰好 3 个**（L223 `if (len(circles[0]) == 3)`）。多一个噪点圆、少一个被遮挡的
   环，整帧直接丢弃。赛场上这就是"偶尔没反应"的来源。应该改成"≥3 里按几何约束挑 3 个"
   （共线 + 间距相近 + 半径相近）。
3. **`minRadius=15, maxRadius=50` 是像素硬编码**，绑死在他们那套相机高度和分辨率上。
   我们的相机装法不同，必须重取；而且 `HOUGH_GRADIENT_ALT` 的 `param2=0.95` 是"完美度"
   阈值，对模糊图像很敏感，需要按实拍重新调。

另外 L188 的 `erode_hsv` 名字带 hsv，实际是对 **BGR** 图 `img` 做腐蚀，命名误导；
而且 L188 在整条链路最前面就对全图腐蚀两次（`iterations=2`），对 640×480 下的小色环
可能先把环腐蚀断，再送去 Hough。

**落到我们这边**：替换 `vision_node.py` 的 `detect_rings()`（L160-198）函数体即可，
`$V` 帧、`CLASS_RING`、`candidate_to_robot()` 全不动。前提是先把相机固定、拍一组真实
光照下的样本图——现在一张都没拍，改了也无法判断好坏。

### 4.3 按场景分档的参数（思路）

他们每个 `unit` 分支用不同的面积限幅（2000 / 3000 / 4000），因为同一个颜色在"载物盘上"
和"地上"距相机远近不同，像素面积差好几倍。我们目前只有一个 `--min-area-px 250`。
建议改成 `colors.json` 里给每类存一组 `area_px` 区间，或者按 `--task` 分档。这是小改动，
但能省掉一大批"近距离误检远处目标"的麻烦。

## 5. 明确不可用

**像素直发 MCU**（全部 `unit` 分支）。我们的 `board_vision` 快照是
`x_mm/y_mm/yaw_mdeg/conf/age`，`vehicle_app` 的消费方按 mm 用。改成像素要同时重写固件
解析、App 动作编排、以及 [视觉方案](视觉方案.md) 里的全部判据。**没有收益**。

**定长 15 字节协议**。与我们 USART3 上并存的 `TASK` 文本命令冲突——固件按 `$` 开头过滤，
二进制帧会被当成杂行丢掉。而且他们的下行 `ser.read(4)` 没有帧同步，掉一个字节之后
`unit` 和 `unit_target` 永久错位，只能重启。我们的行解析 + CRC8 在这个维度上严格更好。

**"卡尔曼滤波"**（L15-92）。这不是卡尔曼：`transitionMatrix` 是单位阵（没有速度状态）、
没有初始化 `statePost` / `errorCovPost`、`last/current_measurement` 三个变量赋值后从未
参与运算（死代码）。实际行为等价于一个固定系数的指数平滑。要用就直接写 EMA
（`y = a*y + (1-a)*x`，a 取 0.6~0.8），参数含义比这套清楚。

**二维码分支**（L553-604）。每帧循环里 `cv2.VideoCapture(2)` 新建、用完 `release()`，
一次开机能耗时几十到几百毫秒；`QRCodeDetector()` 也在循环里重建。这个写法在他们车上
能跑，但不值得学——我们 `Tools/rpi_task_link.py` 是常开相机 + 按内容去重，已实板跑通。

**Jetson 专属环境**。`/dev/ttyCH341USB0` 是 Jetson 上 CH340 的名字；我们是树莓派 4B，
用 `/dev/serial0`（ttyAMA0）。

**硬编码 HSV 三色**。他们只覆盖红/绿/蓝，且阈值是实车现场调的常数。我们要六色
（1红 2黄 3蓝 4绿 5黑 6浅蓝），必须用自己的 `calib_color.py` 标，抄不了。

## 6. 相机数量：已确认同为双相机

他们**用两个相机**：`VideoCapture(0)` 看目标，`VideoCapture(2)` 专门看竖直的 A4 二维码板。

**2026-11-08 用户确认本工程也是两个摄像头**：一个专扫二维码，一个识别物料。
之前的疑点（俯视相机看不到立着的二维码板）因此不成立——扫码走独立相机。

但由此暴露出一个必须现在解决的问题：**两个程序不能同时占用 `/dev/serial0`**。
`Tools/rpi_task_link.py` 与 `Tools/vision_node.py` 都是各自 `serial.Serial(...)` 打开同一个口，
同时跑必然有一个抛 `Permission denied`（或者更糟：两个都打开成功，
字节交错、CRC 全错）。而这两个进程恰好要在同一轮任务里先后发 `TASK` 和 `$V`。

处理方式见第 7 节第 0 步。

## 7. 建议的落地顺序

**先别改算法代码。** 现在 `Tools/vision/` 十件套一次都没上过树莓派，`calib_*.json` 一个都没有
（2026-11-16 已在 PC 上验过相机画面、图像源换算和 `$V` 帧编码；树莓派仍未跑）。
在这种状态下把他们的算法搬进来，只是把"不能跑的代码"换成另一份"不能跑的代码"。

**第 0 步（写任何代码之前）：把两个相机钉成固定设备名。**
树莓派上 USB 相机的 `/dev/videoN` 编号会随插拔顺序变，今天是物料相机明天就变成扫码相机。
按 USB 口（或序列号）建 udev 规则，固定成 `/dev/cam_target` 与 `/dev/cam_qr`，
之后所有脚本只认这两个名字。顺带解决 `/dev/serial0` 被两个进程抢的问题——
**串口只有一个进程能持有**，做法是把扫码并进 `vision_node.py` 的一个线程，
用同一个 `link` 发 `TASK`，不要两个脚本各开一个 `serial.Serial`。

1. 两路相机各自出画面：`python3 vision_node.py --camera /dev/cam_target`，
   扫码那路单独验 `rpi_task_link.py`。**这一步只验"有没有画面"，不看识别对不对。**
   （2026-11-16：实时画面默认就开，不用再加 `--preview`。）
2. 拍一组真实光照样本图（载物盘 / 六色物料 / 色环，各 10 张以上），存进 `Tools/vision/samples/`：
   `python3 vision_node.py --camera /dev/cam_target --save-dir samples/raw --save-every 10`。
   （2026-11-16：`--save-dir` 已实现，原"还没有采集脚本"一条作废。）
3. 用这批图验算法，再标一次五点单应 `calib_plane_h.py`（不需要内参、不需要棋盘格）
   → 四角残差 < 3 mm。（2026-11-16：`calib_intrinsic.py` / `calib_plane.py` 已删除。）
4. 标定过线之后，再替换 `detect_rings()`，用同一批图对比改前/改后的检出率。
5. 最后才谈把 4.1 的像素判据并进 `$V` 帧（要改 `board_vision.h` 和固件解析，属于独立一步）。

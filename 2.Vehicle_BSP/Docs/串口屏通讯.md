## 协议（本模块实现的）

**STM32 → 屏幕**：ASCII 文本指令，**必须以 `0xFF 0xFF 0xFF` 结尾**。

```
n0.val=123<FF FF FF>
t0.txt="ABC"<FF FF FF>
click b0,1<FF FF FF>
page 1<FF FF FF>
```

**屏幕 → STM32**：屏幕自己用 `printh` 发，本模块按 `FF FF FF` 切帧，然后分类：

| 帧内容 | 长度 | 含义 | 交给谁 |
|---|---:|---|---|
| `<code>` | 1 | 屏幕的指令返回状态码 | 模块自动处理，见下 |
| `0x55 p1 p2 p3` | 4 | 自定义帧（和参考工程约定一致） | `Hmi_OnAppFrame(p1,p2,p3)` |
| `0x65 page comp event` | 4 | 触摸事件帧 | `Hmi_OnTouch(page,comp,event)` |
| 其它 | — | 记为坏帧，`Hmi_BadFrames()` 计数 | — |

**返回状态码**：屏幕每执行一条指令都会回一个码。`0x01` = 成功（不打印，否则刷屏），
其它码会转发到调试串口 USART1，例如：

```
HMI return 0x1A: variable name invalid
HMI return 0x1C: parameter invalid
```

常见码：`0x00` 指令无效、`0x01` 成功、`0x02` 对象/变量名无效、`0x03` 操作无效、
`0x04` 赋值无效、`0x1A` 变量名无效、`0x1C` 参数无效、`0x1F` IO 操作失败。
完整列表见 <http://wiki.tjc1688.com/return/index.html>。

**这个状态码非常有用**：接线错、波特率不匹配、控件名写错，都会在这里暴露出来 ——
控件名打错会直接回 `0x1A`，比"屏幕上什么都不动"好排查得多。

## 和参考工程的三处必要改动

参考工程是 F103 + 裸 HAL 串口写的，直接抄会出问题，移植时改掉了这些：

1. **发送方式**。参考工程的 `uart_send_char()` 每次调用 `HAL_UART_Transmit_IT()`
   （异步发送），却不等待上一次发完 —— 连续调用会返回 `HAL_BUSY` 并**丢字符**。
   它自己的头文件里也写了"使用前请将 HAL_UART_Transmit_IT() 改为你的串口发送
   单字节函数"。本模块改成把整条指令拼好后**一次** `Serial_Write(SERIAL_HMI,...)`
   （阻塞式，等到发完），既不会丢字节，调用次数也少得多。
2. **接收方式**。参考工程用 `HAL_UART_Receive_IT(&huart2, RxBuffer, 1)` 逐字节重启
   中断，还要自己实现 `HAL_UART_RxCpltCallback`，并再开一份 500 字节环形缓冲。
   本工程的 `board_comm.c` **已经有** USART6 的中断接收环形缓冲（256 字节）和
   `Hmi_Poll()` 用的 `Serial_ReadByte(SERIAL_HMI)`，所以直接复用，
   **没有**新增环形缓冲，也不碰 HAL 的 UART 回调。
3. **参考工程 `deleteRingBuffer()` 有个 bug**：`return;` 写在了 `for` 循环体里面，
   所以 `udelete(7)` 实际只删掉 1 个字节，解析完一帧后缓冲区不会正确前移。
   本模块不依赖那个函数，所以不存在这个问题。

另外参考工程挂在 USART2 @ 115200，本工程用工程已有的 USART6 @ 115200。

## 接口

```c
#include "board_hmi.h"

/* 初始化 + 主循环轮询（收字节在 USART6 中断里完成，这里只是拼帧） */
void Hmi_Init(void);
void Hmi_Poll(void);

/* 单片机 -> 屏幕 */
void Hmi_SendRaw(const char *command);                 /* 原文 + FF FF FF */
void Hmi_SetText(const char *object, const char *text);/* t0.txt="..." */
void Hmi_SetValue(const char *object, int32_t value);  /* n0.val=123 */
void Hmi_Click(const char *object, uint8_t pressed);   /* click b0,1 / 0 */
void Hmi_SetVisible(const char *object, uint8_t visible);
void Hmi_SetPage(uint8_t page);                        /* page 1 */
void Hmi_SetFont(const char *object, uint16_t font_id);/* 在已有字库间切换 */
void Hmi_Printf(const char *format, ...);              /* 格式化 + FF FF FF */

/* 注意：TJC 的 obj.x / y / w / h 是只读属性，串口写入会回 0x1C；
   对齐用 xcen / ycen，sta 是字体渲染方式（单色/灰度）。
   因此本模块不提供改布局/对齐的接口，控件位置必须在上位机里设定。 */

/* 诊断 */
uint32_t Hmi_Frames(void), Hmi_AppFrames(void), Hmi_TouchFrames(void);
uint32_t Hmi_BadFrames(void), Hmi_ReturnCodes(void);
uint32_t Hmi_TxBytes(void), Hmi_TxTruncated(void);
uint8_t  Hmi_LastReturnCode(void);
const char *Hmi_ReturnCodeText(uint8_t code);

/* 应用钩子：默认是空实现，覆盖它们即可（弱符号，不覆盖也能链接） */
void Hmi_OnAppFrame(uint8_t param1, uint8_t param2, uint8_t param3);
void Hmi_OnTouch(uint8_t page, uint8_t component, uint8_t event);
```

用法就是：`Hmi_Init()` 一次，然后在主循环里反复 `Hmi_Poll()`。

```c
Hmi_Init();
Hmi_SetText("t0", "hello");
Hmi_SetValue("n0", 123);
for (;;) {
  Hmi_Poll();            /* 必须先收，再干别的 */
  ...
}
```

带小数位的 `x0` 不是浮点：TJC 用控件的 `vscope` 属性决定小数点位置，
所以 `Hmi_SetValue("x0", 1234)` 在 `vscope=2` 时屏幕显示 `12.34`。
本模块**完全不使用浮点**，和工程其它部分的风格一致。

## 屏幕端要怎么设置

1. **波特率必须和 `BOARD_HMI_BAUD` 一致**（当前 115200）。
   屏幕工程里写 `bauds=115200`，或用 TJC 上位机把波特率设成 115200。
   **这一条对不上就什么都收不到**，而且没有任何报错 —— 先确认这一项。
2. **控件名要和测试程序里的一致**，否则会收到 `0x1A`：
   - `t0`、`t1` —— 两个文本控件，**必需**，分别显示 `156+123` 和 `+516+231`
     （字高 12 mm 在 3.2" 屏上是 59 px，必须两个控件才能排下，见后面的排版表）
   - `msg` —— 文本控件，**可选**，只用于回显屏幕上报的内容
     （屏幕上没有就把 `Tests/Src/hmi_smoke.c` 里的 `HMI_MSG_OBJECT` 改成已有的控件名，
     或者把回显那几行删掉）

   名字不同就改 `hmi_smoke.c` 顶部的 `HMI_LINE1_OBJECT` / `HMI_LINE2_OBJECT` /
   `HMI_MSG_OBJECT`，或者改屏幕工程。
3. **屏幕主动上报**（双向通讯的"上行"）在控件的触摸事件里写 `printh`，
   **注意必须自己补上 `ff ff ff` 结尾**（`printh` 是原样发字节，不自动加结束符）：

   | 屏幕端触摸事件代码 | MCU 收到 | MCU 的反应 |
   |---|---|---|
   | `printh 55 01 04 01 ff ff ff` | `55 01 04 01` | `msg.txt="led 4 is on"` |
   | `printh 55 01 04 00 ff ff ff` | `55 01 04 00` | `msg.txt="led 4 is off"` |
   | `printh 55 02 64 00 ff ff ff` | `55 02 64 00` | `msg.txt="h0.val is 100"` |
   | `printh 55 03 00 00 ff ff ff` | `55 03 00 00` | `msg.txt="h1.val is 0"` |
   | `printh 65 00 01 01 ff ff ff` | `65 00 01 01` | 打印触摸事件到调试串口 |

   这些和参考工程 `main.c` 里的注释是一套，屏幕端不用改。
4. **中文文本要用 GB2312**。TJC 屏的字库是 GB2312，直接从 MDK 里发 UTF-8 中文
   会显示成乱码。本工程源码是 UTF-8，所以发中文前要先转码，或者干脆只用英文/数字。
   本模块的示例全部用 ASCII。

## 接线

| STM32 | 串口屏 |
|---|---|
| PC6 (HMI_TX, USART6_TX) | 屏的 RX |
| PC7 (HMI_RX, USART6_RX) | 屏的 TX |
| GND | GND |
| 5V | 屏的 5V（屏要独立供电，别从板子 3V3 取） |

**TX/RX 是交叉接的**（板子 TX → 屏 RX）。接反了收不到任何返回码，
调试串口上会一条 `HMI return ...` 都没有 —— 这也是一个很好的排查信号：
**正常情况下每发一条指令都应该收到一个返回码**。

## 上板验证步骤

1. 断电接线，确认共地、屏有独立 5V。
2. 确认屏的波特率 = 115200，并且屏幕工程里有一个叫 `t0` 的文本控件。
3. 烧录 `MDK-ARM/Bench_Tests.uvprojx` 的 `HMI` Target。
4. 接调试串口 USART1（115200），应看到：

   ```
   HMI test ready: USART6 PC6=TX PC7=RX, 115200 8N1
   HMI test: screen baud rate must match, otherwise nothing is received
   HMI test: sending t0.txt="156+123+516+231" every 3000 ms
   ```

5. **屏幕上 `t0` 应该显示 `156+123+516+231`**，并且每 3 秒重发一次
   （屏幕中途重启也能自己恢复）。**同时调试串口上不应该出现任何
   `HMI return 0x..` 报错** —— 没有报错就说明屏幕认了这条指令。
6. 在屏幕上触发上面表格里的触摸事件，`msg` 控件应显示对应文字，
   调试串口应看到 `HMI app frame 55 01 04 01` 之类的行。
7. 排查：
   - **一条返回码都没有** → 波特率不匹配、TX/RX 接反、或屏没有共地。
   - **`0x1A`** → 控件名写错。屏幕工程里必须有 `t0`（和可选的 `msg`）。
   - **`Hmi_BadFrames()` 在涨** → 屏幕发的帧长度或帧头不符合约定，
     检查 `printh` 是不是漏了 `ff ff ff`。
   - **`Serial_Dropped(SERIAL_HMI)` 非 0** → `Hmi_Poll()` 调用得不够勤，
     256 字节的接收缓冲被冲掉了（115200 波特率下约 22 ms 的量）。

## ⚠ 最常见的误解：烧了 HMI Target，屏上怎么还是老样子？

**因为屏和 STM32 是两个完全独立的程序，各有各的下载。**

| | 程序在哪 | 用什么下载 | 决定了什么 |
|---|---|---|---|
| **STM32** | `MDK-ARM/Bench_Tests.uvprojx` 的 `HMI` Target → `MDK-ARM/Bench_Tests/HMI/HMI.hex` | Keil + ST-Link/J-Link 烧到 **MCU** | STM32 发什么串口指令 |
| **屏幕** | 屏幕的 `.HMI` 工程 | **USART HMI 上位机** + 屏自己的下载口 | 屏上显示什么、有哪些控件 |

**烧 STM32 不会、也不可能改变屏上显示的内容。** 屏永远显示"上一次下载到屏里
那个工程"的画面 —— 你现在看到官方例程，就是因为屏里装的还是那个例程。

### 为什么单片机"改不动"官方例程的画面

TJC 的串口指令**只能修改已经存在的控件的属性**：

```
t0.txt="156+123"     ← 把已存在的 t0 的文字改掉   ✅ 能用
t0.x=0 / t0.w=320    ← 把已存在的 t0 挪位置/改宽   ✅ 能用
新建一个叫 t0 的控件                              ❌ 串口做不到
```

**串口创建不了控件。** 所以如果官方例程里没有 `t0` / `t1` 这两个控件，
单片机发 `t0.txt="156+123"` 会被屏幕拒绝（回 `0x1A` = 变量名无效），
屏继续显示它自己例程的内容。**这就是你看到的现象，完全正常。**

所以要显示 `156+123` / `+516+231`，**必须先在屏幕工程里存在 `t0` / `t1` 两个文本控件
并下载到屏**。这一步只能在 USART HMI 上位机里做，固件替代不了。

### 30 秒确认到底卡在哪

**接上调试串口**（USART1：PA9=TX、PA10=RX，**115200 8N1**），复位板子：

| 调试口看到 | 说明 | 下一步 |
|---|---|---|
| 每 3 秒一次 `HMI return 0x1A: variable name invalid` | ✅ **接线和波特率都对**，只是屏上没有 `t0`/`t1` | 去上位机建控件（下面两条路） |
| 一条 `HMI return` 都没有 | 屏波特率不是 115200 / TX-RX 接反 / 没共地 | 先解决通信 |
| 连开机横幅都没有 | 调试串口本身没接对，或固件没烧进去 | 检查 PA9/PA10 和烧录 |

**没有调试串口也能验**：拿 USB-TTL 直接接屏（屏 TX→适配器 RX、屏 RX→适配器 TX、共地），
用 SSCOM（`资料\5.软件工具\串口助手SSCOM_v5.13.1.zip`）在 **115200、十六进制发送**下发：

```
74 30 2E 74 78 74 3D 22 41 42 43 22 FF FF FF      ← 就是 t0.txt="ABC" + FF FF FF
```

- 屏上某个文本框变成 `ABC` → 说明 `t0` 存在
- 回 `1A FF FF FF` → 屏上没有 `t0`
- 什么都没回 → 波特率不对

### 两条路

**路 A（推荐）：建最小屏幕工程。** 按「从零建一个最小屏幕工程」一节做，
新建 320×240、波特率 115200、第 0 页放 `t0`/`t1` 两个文本控件、建 59 px 字库套上、下载到屏。
之后本工程的固件直接就能用，不用改代码。

**路 B（先不改屏，只验证链路）：把宏指到官方例程里已有的控件名。**
在 USART HMI 里打开官方例程，看主页面已有的文本控件叫什么（常见就是 `t0`、`t1`），
然后改 `Tests/Src/hmi_smoke.c`：

```c
#define HMI_LINE1_OBJECT  "t0"    /* 改成例程里真实存在的控件名 */
#define HMI_LINE1_TEXT    "HELLO" /* 先用短字符串试，避免被例程的控件宽度截断 */
#define HMI_LINE2_ENABLE   0
```

重编译下载。**能看到 `HELLO` 就证明整条链路通了**，只是例程的字库字号不合适而已。

## 从零建一个最小屏幕工程（不跑例程）

**不需要跑 TJC 的官方例程。** 屏上要"只显示内容、别的什么都不干"的话，
自己新建一个空工程反而更干净 —— 没有多余的页面、按钮和触摸事件。

### 详细步骤（照着点）

> 上位机的菜单/按钮名称各版本略有差异，下面按常见叫法写。

**① 新建工程**

USART HMI → 菜单「文件 → 新建」。弹窗里填：

- 型号/器件：选 **TJC3224T132_011**；列表里没有就选分辨率 **320×240**
- 方向：**横向**（0°）
- 工程名/路径：随便，例如 `lift_display`

**② 设波特率**

在「工程设置 / 系统参数」里把**波特率改成 115200**（有些版本是直接改 `bauds` 属性）。
**这一步忘了，后面屏和 STM32 一句话都说不上，而且没有任何报错提示。**

**③ 放两个文本控件**

1. 左侧工具栏选「文本 / Text」控件（图标通常是 `t`），在第 0 页空白处**点两下**放两个。
2. 选中第一个，在右侧「属性」面板把 **objname** 从默认的 `t0` 确认/改成 **`t0`**；
   第二个改成 **`t1`**。
   （objname 是单片机寻址用的唯一名字，**必须一致**，大小写敏感。）
3. 位置和大小**先随便放** —— 单片机开机时会用串口把两个控件摆到
   0/56/320/64 和 0/120/320/64 并居中。想在上位机里自己摆也行，
   那就把 `hmi_smoke.c` 的 `HMI_APPLY_LAYOUT` 改成 `0`。

**④ 建 59 px 字库并套给两个控件**

1. 选中 `t0`，在属性的「字体」那一栏点右边的 **`...`** 按钮，进入「字体生成」。
2. 点「添加 / 新建」，填：
   - **字高：`59`**（= 3.2" 屏上的 12 mm；`像素 = 字高mm ÷ 25.4 × 125`）
   - 编码：**ASCII**（要显示 `+` 和数字，ASCII 足够；中文才需要 GB2312）
   - 字体名：随便，如 `f59`；字体样式：宋体或 Arial 都行
3. 确定后，在属性的「字体」下拉里**选中刚才这个字库**。
4. **对 `t1` 重复一遍**，套同一个字库。

⚠ **最容易漏的就是第 3、4 步**：控件建好了但没套字库 → 屏上什么都不显示，
**而且不报任何错**。同理，如果**字色和背景色一样**（属性里的 `pco` / `bco`），
也会"有字但看不见"。

**⑤ 事件全部留空**

`t0`、`t1` 的**触摸事件、弹起事件都不写代码**；第 0 页的**页面加载事件也留空**。
这样屏就是纯被动显示，只认单片机发来的指令，自己不发东西。

**⑥ 编译 + 下载到屏**（两种方式任选）

**方式一：上位机串口下载（常规）**
1. **把屏从 STM32 上拔下来**，接到电脑的 USB-TTL：屏 TX→适配器 RX、屏 RX→适配器 TX、**共地**，屏单独供 5V。
2. 点工具栏的「编译」（把工程编成 `.TFT`），再点「下载 / 联机下载」。
3. 选对 COM 口（波特率上位机会自动协商），点开始。
   **下载期间屏会显示进度条**，不要断电。
4. 下载完成后把屏接回 STM32。

**方式二：microSD 卡下载（没有富余 USB-TTL 时）**
1. 编译后得到 `.TFT` 文件（通常在工程目录下）。
2. 拷到 **microSD 卡根目录**，插进屏的卡槽。
3. 给屏上电，屏会自动把 `.TFT` 刷进去，完成后提示拔卡/断电。
4. 拔卡、断电、重新上电。

**⑦ 通过判据**

屏上应该立刻显示：第一行 `156+123`、第二行 `+516+231`，
两行水平居中、上下分布均匀、不被截断。

**然后拿尺子量数字实际高度**（见下面「字高 12 mm」那节的说明）。

### 如果上位机里已经有那个官方例程的 `.HMI`

那比新建更省事：**直接打开它**，跳过 ①，只做 ②④⑤⑥，
再把已有的两个文本控件的 objname 改成 `t0` / `t1`（或反过来改
`hmi_smoke.c` 里的宏去对上它们的名字）。

`t0`/`t1` 这两个名字在 TJC 例程里非常常见，很可能本来就存在，那就连新建控件都省了。

### 最小工程对应的固件配置（显示 `156+123+516+231` 用这套）

**当前固件已经就是这个配置，一行都不用改。** 供核对：

```c
#define HMI_LINE1_OBJECT  "t0"        /* 第一行控件，必须和上位机里一致 */
#define HMI_LINE1_TEXT    "156+123"
#define HMI_LINE2_OBJECT  "t1"        /* 第二行控件 */
#define HMI_LINE2_TEXT    "+516+231"
#define HMI_LINE2_ENABLE   1          /* 两行都要（15 字符一行放不下） */
#define HMI_APPLY_LAYOUT   1          /* 布局由单片机用串口设 */
#define HMI_FONT_ID      (-1)         /* 字库在上位机里建好并套给控件了，不用切 */
```

- 如果屏幕工程里**只有一个控件**（只显示短内容），把 `HMI_LINE2_ENABLE` 改成 `0`，
  固件就不会再往不存在的 `t1` 发指令（那会每 3 秒回一次 `0x1A` 刷屏）。
- `HMI_FONT_ID = (-1)` 表示**不发** `t0.font` 指令，沿用你在上位机里套给控件的字库 ——
  自己新建字库时就用 `(-1)`。只有想复用例程里已有字库时才填编号。

### 文本控件 vs 数字控件：按显示内容选

| 要显示的内容 | 用哪种控件 | 固件接口 | 发出的指令 |
|---|---|---|---|
| 带符号的字符串（如 `156+123`、`OK`） | **文本控件** `t0` | `Hmi_SetText("t0", "...")` | `t0.txt="156+123"` |
| **纯数字**（如 `123`、测量值） | **数字控件** `t0` | `Hmi_SetValue("t0", 123)` | `t0.val=123` |

- **纯数字用数字控件更省事**：不用打引号，屏幕还能用 `vscope` 属性控制小数点
  （`vscope=2` 时 `t0.val=1234` 显示 `12.34`）。
- **数字控件放不了 `+`、字母**：`t0.val=156+123` 会被当成算式或直接报错，
  所以 `156+123+516+231` 这种必须用文本控件。
- 两种控件的 objname 都可以叫 `t0`，**固件靠调用的接口区分**，不用改名字。

### 屏幕会回状态码 —— 这是好事，别关掉

最小工程里屏幕**每执行一条指令仍会自动回一个状态码**（`0x01` = 成功）。
这是白送的验证手段：调试串口上没有 `HMI return 0x..` 就说明屏全认了；
收到 `0x1A` 说明控件名写错了。**不需要在屏幕工程里写任何代码。**

## 让屏幕显示指定文字，以及"字高 12 mm"这件事

### 结论：**字高不能由单片机设置**

TJC 的字体（字库）是在 **USART HMI 上位机**里"字体生成"出来、编译进屏幕工程的，
烧录时一起进屏。单片机这边**没有任何指令可以设定字号**，只能用 `控件.font=<id>`
在**屏幕工程里已经存在的字库**之间切换。给了不存在的 id，屏幕会回
`0x1A` / 无效字体 ID（[参考讨论](https://en.eeworld.com.cn/bbs/forum.php?mod=viewthread&tid=1227465&page=1#1)）。

所以"显示 `156+123+516+231`，字高 12 mm"要分两边做：

| 谁做 | 做什么 |
|---|---|
| **屏幕端**（上位机） | 建文本控件，在"字体生成"里按**像素**建 12 mm 对应的字高，赋给控件，设置坐标/宽度/对齐/颜色 |
| **单片机端** | `Hmi_SetText(...)` 把字符发过去 —— 本工程的 `HMI` Target 已经在做了 |

**本项目的屏是 TJC3224T132_011（T1 3.2"，320×240），结论是 59 px、必须分两行，
具体数值见后面「本项目的实际参数」一节。** 下面是通用的算法，换屏时用得上。

### 12 mm 等于多少像素：取决于你的屏

上位机的字高填的是**像素**，12 mm 换算成多少像素由屏幕像素密度决定：

```
像素 = 12 / 25.4 × DPI,   DPI = √(宽² + 高²) / 屏对角线英寸
```

| 屏型号（常见 TJC） | 分辨率 | DPI | **12 mm ≈** |
|---|---|---:|---:|
| TJC3224T024（2.4"） | 320×240 | 166.7 | **79 px** |
| TJC3224T028（2.8"） | 320×240 | 142.9 | **67 px** |
| **TJC3224T132（3.2"）← 本项目** | 320×240 | **125.0** | **59 px** |
| TJC4832T035（3.5"） | 480×320 | 164.8 | **78 px** |
| TJC4827T043（4.3"） | 480×272 | 128.3 | **61 px** |
| TJC8048T050（5.0"） | 800×480 | 186.6 | **88 px** |
| TJC8048T070（7.0"） | 800×480 | 133.3 | **63 px** |
| TJC1060T070（7.0"） | 1024×600 | 169.5 | **80 px** |

（按标称对角线算，实际可视区略小，所以实际字高会略大一点点。）
先量一下你的屏型号或分辨率，再照上表填；或者反过来，建一个字号后量屏幕上
实际显示高度，按比例微调。

### ⚠ 15 个字符按 12 mm 高排一行，小屏放不下

`156+123+516+231` 是 15 个字符。ASCII 数字/符号的前进宽度约为字高的 0.5~0.6 倍，
所以这行文字大约需要 **15 × 12 × 0.55 ≈ 99 mm** 的宽度：

| 屏 | 屏宽 | 99 mm 放得下？ |
|---|---:|---|
| 2.4"（320×240） | 48.8 mm | ❌ 放不下 |
| 2.8"（320×240） | 56.9 mm | ❌ 放不下 |
| **3.2"（320×240）← 本项目** | **65.0 mm** | ❌ 放不下 |
| 3.5"（480×320） | 74.0 mm | ❌ 放不下 |
| 4.3"（480×272） | 95.0 mm | ❌ 勉强不行 |
| 5.0"（800×480） | 108.9 mm | ✅ |
| 7.0"（800×480） | 152.5 mm | ✅ |
| 7.0"（1024×600） | 153.4 mm | ✅ |

**也就是说 12 mm 字高只有 5 寸及以上的屏才排得下一行。本项目的 3.2" 屏属于
"放不下"，已按需要改成两行显示**（见后面「两行排版」）。小屏可选的三种做法：

1. 把字高降到能放下（3.5" 屏最多约 74/15/0.55 ≈ 8.9 mm）；
2. 分两行显示（需要两个文本控件，或者用控件自动换行）；
3. 换大屏。

### 屏幕端上位机的具体步骤（本项目：59 px、两个控件两行）

1. 打开你的屏幕工程（就是现在跑的那个官方例程工程）。
2. 点字体属性 → **字体生成**：新建一个字库，**字高填 59**（= 12 mm）。
   编码选 ASCII 就够（纯数字和 `+`）；以后要显示中文得另建 GB2312 字库。
3. 在主页面上放**两个文本控件**，objname 分别改成 **`t0`** 和 **`t1`**
   （或改成别的名字，然后同步改 `Tests/Src/hmi_smoke.c` 顶部的
   `HMI_LINE1_OBJECT` / `HMI_LINE2_OBJECT`）。
4. 两个控件都套用刚才那个 59 px 字库，然后按这个表设属性：

   | 控件 | x | y | 宽 w | 高 h | 对齐 sta | 显示内容 |
   |---|---:|---:|---:|---:|---:|---|
   | `t0` | 0 | 61 | 320 | 60 | 1（居中） | `156+123` |
   | `t1` | 0 | 120 | 320 | 60 | 1（居中） | `+516+231` |

   宽度给整屏 320 并对齐居中，两行就会自动水平居中，换字体也不会跑偏；
   如果字的下缘被切掉，把 `h` 加到 62~64。
5. 保存、编译、**下载到屏幕**（这一步必须在仿真里看效果，TJC 上位机自带仿真）。
6. 如果想让单片机在多个字号之间切换，就在上位机里多建几个字库，
   记下编号，然后调 `Hmi_SetFont("t0", <id>)` / `Hmi_SetFont("t1", <id>)`。

### 想显示静态文字的话，也可以完全不用单片机

如果这串文字是固定的、不需要单片机参与，直接在屏幕工程里给 `t0`/`t1` 的
`txt` 属性分别填上 `156+123` 和 `+516+231` 就行，单片机什么都不用发。
本工程的 `HMI` Target 会每 3 秒重发一次同样的文字，内容一样所以不会冲突。

### 本项目的实际参数（TJC3224T132_011）

> **屏**：淘晶驰 T1 系列 3.2" 串口屏 **TJC3224T132_011**（IPS）→ 分辨率 **320×240**

按 `TJC<宽><高>T<系列><尺寸>` 的命名规则，`3224` 就是 320×240。据此：

| 项 | 数值 | 算法 |
|---|---:|---|
| 对角线像素 | 400 | √(320² + 240²) |
| **DPI** | **125.0** | 400 / 3.2" |
| 可视区 | **65.0 × 48.8 mm** | 320÷125×25.4, 240÷125×25.4 |
| **12 mm 字高 =** | **59 px** | 12 ÷ 25.4 × 125 = 59.06 |
| 12 mm 字高一行最多 | **约 9 个字符** | 65.0 ÷ (12 × 0.55) = 9.85 |
| 15 个字符一行需要 | **99.0 mm** | 放不下（屏宽只有 65.0 mm） |

所以上位机"字体生成"里 **字高填 59 px**，然后按两行排版。

> ⚠ **"字高 59 px"是字体名义高度（em），不等于数字笔画的实际高度。**
> ASCII 数字的实际墨迹高度大约只有名义高度的 **0.7 倍**，所以 59 px 的字体里
> 数字看起来只有约 **41 px ≈ 8.4 mm**（汉字是全角，会占满 12 mm）。
> 上板后**一定要拿尺子量一下屏幕上数字实际多高**，再决定要不要调：
>
> | 你的"12 mm"指的是 | 名义字高 | 排得下吗 |
> |---|---:|---|
> | 字体大小（em）12 mm | **59 px** | ✅ 两行放得下（本工程当前按这个做） |
> | 数字笔画高度 12 mm | **84 px**（= 12÷0.7） | ❌ **这块 3.2" 屏物理上做不到** |
>
> 第二行的原因：84 px 字体下一个字符要 84×0.55 ≈ 46 px，320 px 宽**一行只能放 6 个字符**，
> 15 个字符要 **3 行**；而 3×84 = 253 px **已经超过屏高 240 px**。
> 这种情况只能降低要求（减小笔画高度）、缩短文本，或者换更大的屏。

### 两行排版（TJC3224T132_011 的具体数值）

`156+123+516+231` 拆成两行，每行都不超过 8 个字符，都能放进 65 mm：

| 控件 | objname | 显示内容 | 宽度占用 |
|---|---|---|---:|
| 第一行 | **`t0`** | `156+123` | 46.2 mm |
| 第二行 | **`t1`** | `+516+231` | 52.8 mm |

（也可以换成 `t0`=`156+123+` / `t1`=`516+231`，7+8 与 8+7 都放得下；
但不要切成 11+4，11 个字要 72.6 mm，会超宽被截断。）

两行共 2×64 = 128 px，屏高 240 px，垂直居中后的控件属性（**由单片机用串口设定**，
上位机里不用手设）：

| 控件 | x | y | 宽 w | 高 h | 对齐 sta |
|---|---:|---:|---:|---:|---:|
| `t0` | 0 | **56** | **320** | **64** | 1（居中） |
| `t1` | 0 | **120** | **320** | **64** | 1（居中） |

宽度都设成整屏 320、对齐设成居中，两行就会自动水平居中，
不用管字体实际的前进宽度是多少 —— 这样换字体也不会跑偏。
`h` 用 64（比 59 px 字体多一点余量），两行正好上下相邻不重叠。

水平方向的占用（59 px 字体，屏宽 320 px）：

| 行 | 内容 | 估算宽度 | 居中后左右留白 |
|---|---|---:|---:|
| 1 | `156+123`（7 字符） | ~227 px | 各 ~46 px |
| 2 | `+516+231`（8 字符） | ~260 px | 各 ~30 px |

两行都放得下。**再长就危险了** —— 9 个字符约 292 px 已经贴边，10 个字符就超宽。

## 验证状态

- **编译**：2026-10-01，`HMI` 全量重建为 0 Error(s), 3 Warning(s)，HEX 已生成；3 条警告均来自 ST HAL 的 `Banks` 参数。弱符号回调由 `hmi_smoke.c` 覆盖 BSP 默认空实现。
- **实板**：尚未烧录验证。屏端波特率、控件名、`printh` 帧格式、TX/RX 交叉接线和界面恢复都需要上板确认。
- **2026-10-17 变更（未编译、未上板）**：`hmi_smoke.c` 改为任务码显示模式，依赖 USART3 收 `TASK`/`STAT`；控件要求变为 `t0`～`t3` 四个文本控件。详见 [串口屏任务码显示](串口屏任务码显示.md)。本文其余"固定显示 156+123"的步骤不再对应当前 HMI Target 的默认行为。

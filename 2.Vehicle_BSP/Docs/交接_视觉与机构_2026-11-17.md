### 2.2 视觉闭环链路（重要）

```
蓝牙/USB 命令 → Align_StartEx(cls, tol, track)
   ├─ 回 OK TRACK/ALIGN ...，并往 USART3 发 "$C,<cls>\n"
   ├─ Align_Poll()：每 100 ms 按 $V 误差给四轮速度；锁定 = 停稳 + 连续 3 帧在容差内
   ├─ TRACK：锁定后继续跟
   └─ GRAB：锁定 → Align_TryCompleteForGrab() → Pick_GrabStart(place)
            → 取料 → 放料（ROT -132° → 松 → 载物盘走一格 → 转回 → 回顶）
```

关键状态：`align.c` 里的 `track/locked/settle_hits/vff_*`；前馈 `AL_TRACK_FF_MILLI=700`，
阶跃剔除 `AL_TRACK_FF_REJECT_MM_PER_S=120`，解锁滞回 `AL_TRACK_UNLOCK_MARGIN_MM=5`。

|---|---|---|
| 物料台取料位 | 8000 | `PK_CYC_LIFT_DOWN_PULSES` |

41000 脉冲 ≈ 102.5 mm（顶部到地面）。导程是标称值，换丝杆后要重新折算。

### 3.1 扫码（已并进 `main.py`，独立扫码相机）

- `main.py` 默认同时打开两路相机：`--camera` 视觉、`--qr-camera` 扫码；

- 扫到后发 `TASK <code>` 上屏，解析两批顺序并写 `task_plan.json`；
- 命令：
  ```bash
  python3 main.py --camera /dev/cam_target --qr-camera /dev/video2
  python3 main.py --camera 0 --qr-camera 1
  python3 main.py --no-send          # 只预览，不开串口
  ```
- 扫码和视觉在同一个进程里，不用再停一个起一个；
- `rpi_task_link.py` 仍是独立的已验链路工具（只发 TASK、不解析顺序），需要时可用。

### 3.2 任务码解析（`task_rules.py`，`main.py` 自动调用）

- `main.py` 收到 `@SCAN`、扫码成功后自动 `task_rules.parse()`：
  打印两批颜色顺序，写 `task_plan.json`；
- 规则：4 组三位数；第 1 组=第一批颜色顺序，第 2 组=第一批圆环号，第 3 组=第二批颜色，
  第 4 组=第二批圆环号；颜色 1红 2黄 3蓝 4绿 5黑 6浅蓝；
- 第 2 组只按圆环号用，粗加工区/暂存区的归属不用管；
- 单测规则：`python3 task_rules.py 156+123+516+231`；
- 固件：`SCAN` → 树莓派 `@SCAN`；`TASK <code>` 写串口屏 page 0 的 `t0/t1`；
  `STAT <g> <p>` 写 page 1 的 `t2/t3`（HMI 已并进 `Vehicle_Integrated`）；
- 颜色漏检兜底：`--shape-fallback`（默认开，`--no-shape-fallback` 关）先按 Canny/自适应/Otsu 轮廓找圆形/圆柱（圆度/填充率/长宽比），
  再在轮廓内判颜色；颜色判不出时按当前类别给目标，避免直接 `no target`。默认关，预览确认后再开。
- `ROT_HOME` 会先回 `ROT_HOME tracked=... target=...`；tracked 超出 ±360 时跳过而不中止任务。
- 扫码窗口默认关（`--qr-preview` 才开），`$V` 终端打印降到 1 Hz。
- 识别门控：ALIGN/GRAB/DROP 启动时固件发 `@DETECT 1`，对准结束/中止发 `@DETECT 0`；
  树莓派只在 `@DETECT 1` 期间做检测，平时关；`--ignore-top` 默认 0.10（上部 10% 不识别）。
- 树莓派下发的 `TASK`/`STAT` 也走 USART3；drop7 起 `Vision_Poll` 把非 `$` 行交给应用层
  （只放行这两类，其它下行丢弃），否则命令会被视觉行解析器吃掉、屏不更新；
- drop8 起 `$C` 环模式带**当前转台角**：`$C,11,<n>,<rot_deg>[,<stage>]`（如 `$C,11,2,132,0`）。
  视觉**默认不叠加**：环和物料同用 `--rot-deg`（90），这是实车验证过的；
  只有相机确实跟着转台转时，才加 `--ring-use-arm`（`rot_eff = rot-deg + 转台角`）。
- drop11 起对准近目标降速：`|e| ≤ 20 mm` 用 `AL_SERVO_GAIN_NEAR_MILLI=800`，最小速度 6 mm/s，
  避免 2 mm 精对时 ±10 mm 极限环；远距离仍用 2500 增益。
- drop13 起 DROP 的两段对准用 **ALIGN 一次性模式**（到容差就 done），不是 TRACK；
  TRACK 锁定后不会结束，DROP 会一直等到 25 s 超时。
- drop9 起圆环放置分**两段对准**：顶部 `stage=0` 粗对（`PK_DROP_ALIGN_COARSE_MM`，默认 15 mm），
  降下去后 `stage=1` 精对（`PK_DROP_ALIGN_TOL_MM`，默认 2 mm）；
  视觉按 stage 切 `--ring-px-per-mm-top`（顶部）/ `--ring-px-per-mm`（底部），顶部不做数字识别。

### 3.3 树莓派侧必须知道的三件事

1. **串口权限**：`/dev/serial0` 在树莓派上可能指向 `ttyS0`（mini UART，权限 `crw------- root tty`）。
   要么 `sudo usermod -aG dialout $USER` + 注销重登 + udev 规则，要么 `dtoverlay=disable-bt` 换成 `ttyAMA0`。
2. **`$C` 是双向的**：USART3 的 TX（PC10）必须接到树莓派 RX，否则换色不生效。
   排查：树莓派 `python3 align_send.py --link-test`，STM32 发 `HINT 3`，应看到 `RX b'$C,3\n'`。
3. **串口控制台抢占**：`/dev/ttyS0` 上的登录控制台会吃掉 `$C` 的前几个字节（表现为只收到 `3\n`），
   用 `raspi-config` 关掉 login shell。

## 5. 圆环放置 `DROP`（2026-11-17 已实现）

### 5.1 顺序（用户定）

**空爪先对准 → 对准后底盘不动 → 从载物台取料 → 下放 → 松开。**

```
空爪转到放料侧 → 降到释放高度（= 对准高度）→ 视觉对准圆环中心（此步底盘动）
→ 升回最高处 → 转回取料侧 → 降到取料位 → 夹料 → 升回最高处
→ 转到放料侧 → 降到释放高度 → 松开 → 抬离 → 回最高处 → 转回取料侧
```

### 5.2 为什么空爪对准

夹着料时料正好挡在相机正中：1 环外径只比料大 3 mm（单边 1.5 mm），内圈基本看不见。
空爪对准能看全 6 个同心圆；对准后底盘不再动，取料/回位只靠 ROT 的回程重复精度。

### 5.3 高度

- **对准高度 = 释放高度**，同一个参数 `PK_DROP_RELEASE_PULSES`（默认 **41000**，顶部→地面）。
- 对准之后不再升降调整，只做"取料 → 转回 → 降下 → 松爪"。
- 想留 1~2 mm 余量就把这个值减 400~800（1 mm = 400 脉冲）。

### 5.4 固件（`App/Src/pick_app.c` 的 `drop_table`，19 步）

| 步 | 动作 |
|---|---|
| 1 | 空爪张开 |
| 2 | ROT +132°（放料侧） |
| 3-4 | 降到释放高度（末段 1200 脉冲慢速） |
| 5 | `CYC_KIND_ALIGN`：`Align_StartExAux(11, 2, 1, <环号>)`，等 `Align_IsActive()` 落下 |
| 6 | 升回最高处 |
| 7 | ROT -132°（取料侧） |
| 8-9 | 降到载物台取料位（4000，末段慢降） |
| 10 | 夹紧 |
| 11-12 | 慢抬离 → 升回最高处 |
| 13 | ROT +132°（放料侧） |
| 14-15 | 降到释放高度 |
| 16 | 松开 |
| 17-18 | 慢抬离 → 升回最高处 |
| 19 | ROT -132°（回取料侧） |

保护：

- 对准失败/超时（`PK_DROP_ALIGN_TIMEOUT_MS` = 25 s）→ 停轴 + **把升降升回最高处**再报错，不会停在半空；
- `STOP` / 手动命令抢占 → 停轴后 `Pick_Poll` 自动把升降升回最高处（drop4 起对所有序列生效）；
- 对准期间 `Align` 的 `$C,11` 会让树莓派自动切到环检测。

### 5.5 视觉：`cls=11` 环模式（`main.py` / 检测库 `align_send.py`）

- 收到 `$C,11[,<n>[,<rot>[,<stage>]]]` 自动从颜色切到环检测，收到 `$C,1..6` 再切回；
- 检测：灰度 → CLAHE(5.0) → 高斯 → `HoughCircles(HOUGH_GRADIENT_ALT, param1=300, param2=0.85)`；
  圆心聚簇（一簇 = 一个环），**只报离夹爪最近的一个**（车停在目标环前，不需要三个都入画）；
- **读数字**：裁环心 → OTSU → 居中最大轮廓 → 64×64 → 与 `digit_templates/1..3.png`
  四方向模板匹配；模板由 `make_digit_templates.py` 从印刷图案照片生成（换图案重跑一次）；
- `$C,11,<n>` 的 n 是**期望环号**（只在底部 stage=1 读数字）：读到数字不一致时 `--ring-digit-check warn`（默认，只提示）/
  `strict`（不发目标，DROP 会因对准超时退出）/ `off`；
- 参数：`--ring-px-per-mm`（**在释放高度量**）、`--ring-min-radius`、`--ring-max-radius`、
  `--ring-param2`、`--ring-digit-min-score`（默认 0.35）；预览画选中的环 + `ring 2 (0.98)`；
- 合成图测试：三环各自读到 1/2/3（score 1.0）；单环 `$C,11,2` 发目标；strict 不匹配不发；warn 照发；
- 顶部 `stage=0` 用 `--ring-px-per-mm-top`（最高处量），底部 `stage=1` 用 `--ring-px-per-mm`（释放高度量）。

### 5.6 上板顺序（第一次务必按这个来）

4. 车停在目标环前，`E 1` → `DROP 1` / `DROP 2` / `DROP 3`（视觉会读数字确认；strict 不匹配会对准超时退出）：
   - 先看它是不是"空爪下去 → 对准 → 上来 → 取料 → 转过去 → 再下去 → 松开"；
   - 中途 `STOP` 试一次，确认会停轴并把升降升回；
5. 量落点：先打 2/3 环（Φ+8/Φ+15，容差 4/7.5 mm），稳了再冲 1 环（1.5 mm）。

### 5.7 参数

| 参数 | 值 | 说明 |
|---|---|---|
| `PK_DROP_RELEASE_PULSES` | 41000 | 释放/对准高度（顶部→地面） |
| `PK_DROP_ALIGN_TOL_MM` | 2 | 对准容差；1 环要 ≤1.5 mm，稳了再压到 1 |
| `PK_DROP_ALIGN_TIMEOUT_MS` | 25000 | 对准阶段超时 |
| `--ring-digit-check` | warn | 数字和期望环号不符时：off/warn/strict |
| `--ring-offset-x-mm` / `-y-mm` | 0 | 放料固定偏置补偿（10 次均值偏多少就填多少） |
| `--ring-px-per-mm` | 现场量 | 释放高度处的 px/mm，颜色那套 1.5 不能直接用 |

### 5.8 还没做的

- 1 环落点精度验证（ROT 回程重复性、升降高度重复性）；
- 3 个环位如果是独立位置，`DROP` 之间要开过去重新对准（底盘一动就得重对）。

## 6. 已知坑（踩过的）

| 现象 | 原因 | 处理 |
|---|---|---|
| 车绕着物料转圈 | 相机装歪 90°，视觉坐标与车体系差 90° | `CAMERA_MOUNT_DEG=90` / `--rot-deg 90`（见 `视觉对准_ALIGN.md` §4.2） |
| 蓝牙换色不生效、日志 `no serial` | 树莓派串口打不开（权限/被占） | `dialout` 组 / udev / 关控制台；`--require-serial` 直接暴露 |
| `$C` 只收到 `3\n` | 串口控制台把前几个字节吃掉 | `raspi-config` 关 login shell 或 `disable-bt` |
| 帧率只有 5 fps | 全检 + 原分辨率太慢 | `--detect-scale 0.5`（默认）/ `--detect single` |
| 手碰一下车冲过头 | 阶跃被当成速度 | `AL_TRACK_FF_REJECT_MM_PER_S=120` 已加 |
| `GRAB` 发了没动作 | 实际发的是 `ALIGN`，或固件版本旧 | `VER` 确认；`GRAB` 首行应为 `OK TRACK` |
| `LIFT` 顶死/回不了位 | 升降无下限位、无编码器 | 分步试；`STOP` 后会自动回位（drop4 起） |
| 断电时不在最高处 | `lift_pos_pulses` 上电清零，软件仍以为在顶 | 先 `IN` 看 top 输入；手动小步向上回顶 → `LIFT ZERO` → `LIFT ?` 为 0，再跑序列。**不要直接 `LIFT 41000`/`DROP`** |
| `PLT` 走格不准 | 连续舵机无反馈，只能按时间 | 每次 413 ms，重复性 ±10~20% |

# 串口屏任务码显示（树莓派 → STM32 → TJC 屏）

比赛流程要求：小车移动到二维码板前读取二维码，得到由四组三位数组成的任务码，
并**把任务码显示在显示装置上**；比赛结束时还要在显示装置上查看
**抓取正确次数和放置正确次数**。

本文是这条链路的联调说明：

```
树莓派 ──USART3 / 115200──► STM32F407 ──USART6 / 115200──► TJC 屏（320×240）
 扫码/图片                     解析 + 校验                     page0: t0/t1 任务码
                              TASK / STAT 命令                page1: t2/t3 统计
```

> **2026-11-17**：`TASK` / `STAT` 和 HMI 初始化已并进 `Vehicle_Integrated`（drop7）。
> 树莓派从 USART3 下发的 `TASK`/`STAT` 由 `Vision_Poll` 的非 `$` 行钩子转给命令解析（只放行这两类），
> 不再需要单独的 `HMI` 台架；`SCAN` 命令让 STM32 往树莓派发 `@SCAN` 触发扫码。
> 扫码 + 解析 + 抓取顺序脚本在 `Tools/vision/task/`（`task_link.py` / `task_rules.py`）。

| 项目 | 内容 |
|---|---|
| 屏型号 | TJC 320×240（具体型号以屏背面为准；本文按 320×240 配置） |
| 屏接口 | USART6，PC6 = HMI_TX，PC7 = HMI_RX，**115200 8N1** |
| 树莓派接口 | USART3，PC10 = RPI_TX，PC11 = RPI_RX，**115200 8N1** |
| STM32 调试口 | USART1，PA9/PA10，115200 |
| 固件入口 | `Bench_Tests.uvprojx` 的 **`HMI`** Target → `Tests/Src/hmi_smoke.c` |
| 树莓派脚本 | `Tools/rpi_task_link.py` |
| 屏协议基础 | [串口屏通讯](串口屏通讯.md)（TJC 指令格式、返回码、字库限制） |

> ⚠ 本文与 `串口屏通讯.md` 的区别：那篇讲 TJC 协议本身和最初的"固定显示 156+123"
> 验证；本文讲**当前固件**的任务码显示模式。两者冲突时，控件要求以本文为准。

## 1. 任务码格式

任务码由四组三位数组成，组间用 `+` 连接，共 15 个字符，例如：

```
156+123+516+231
```

| 组 | 含义 | 取值 |
|---|---|---|
| 第 1 组 | 第一批三个物料的颜色和搬运顺序 | 每位 1..6 |
| 第 2 组 | 第一批物料在粗加工区/暂存区的放置圆环 | 每位 1..6 |
| 第 3 组 | 第二批三个物料的颜色和搬运顺序 | 每位 1..6 |
| 第 4 组 | 第二批物料在粗加工区的放置圆环 | 每位 1..6 |

颜色编号：**1 红、2 黄、3 蓝、4 绿、5 黑、6 浅蓝**。

格式校验在 STM32 和树莓派两端各做一次，规则完全一致：长度必须是 15，
第 4、8、12 个字符（下标 3、7、11）必须是 `+`，其余 12 位必须是 `1`..`6`。
两端都拒绝时都不会改屏上已有内容，只在串口上回错误。

## 2. 串口协议（Pi ↔ STM32）

全部是 **ASCII 单行，`\n` 结尾**，命令不区分大小写。

| Pi 发送 | STM32 回复 | 说明 |
|---|---|---|
| `TASK 156+123+516+231` | `OK TASK` | 校验通过并已刷屏 |
| | `ERR TASK FORMAT` | 长度/字符不合法，屏上内容不变 |
| `STAT 3 5` | `OK STAT` | 抓取正确 3 次、放置正确 5 次，已刷屏 |
| | `ERR STAT FORMAT` / `ERR STAT RANGE` | 参数不是两个整数 / 超过 999 |
| `PING` | `PONG` | 链路测试 |
| 其它 | `ERR UNKNOWN` | 未知命令 |
| 行太长 | `ERR LINE TOO LONG` | 超过 39 字节 |

STM32 开机时还会向 Pi 发一行 `READY`（Pi 脚本可选地读取，读不到不算失败）。
同一条命令的调试回显写在 USART1 上，例如 `TASK SET 156+123+516+231`、
`STAT grab=3 place=5`。

## 3. 屏上显示什么

任务码和统计**分两页**，另有一页启动页，因为 TJC 的串口指令只作用于当前页，而比赛过程中任务码要一直可见、结束时才看统计。

| 页 | 控件 | 字库 | 初始内容 | 收到 `TASK` 后 | 收到 `STAT` 后 |
|---:|---|---|---|---|---|
| 2 | `b0` | 32 px ASCII（ID 0） | 按钮文字 `START` | 不可见 | 不可见 |
| 0 | `t0` | 64 px ASCII（ID 1） | `NO TASK` | `156+123` | 不变（停在任务页） |
| 0 | `t1` | 64 px ASCII（ID 1） | 空 | `+516+231` | 不变 |
| 1 | `t2` | 32 px ASCII（ID 0） | `GRAB OK 0` | 不可见 | `GRAB OK 3` |
| 1 | `t3` | 32 px ASCII（ID 0） | `PLACE OK 0` | 不可见 | `PLACE OK 5` |

为什么拆两行：3.2" 屏 12 mm 字高 = 59 px，15 个字符一行约需 99 mm，
而屏宽只有 65 mm（详细换算见 [串口屏通讯](串口屏通讯.md) 的"字高 12 mm"一节）。
`156+123`（7 字符）和 `+516+231`（8 字符）在 64 px 下约 246 px、282 px，都放得下。

页面切换由 STM32 负责：开机停在 **page 2 启动页**；按 START 后屏端自己切到 page 0 并
用 `printh` 通知固件；收到 `TASK` 切到 page 0，收到 `STAT` 切到 page 1；
每 5 秒的周期刷新**只刷当前页，不切页**，所以任务码不会在运行中被统计页打断。

> ⚠ 屏中途重启会回到第 0 页，任务页会显示工程里的初始值。发送一次 `TASK` 或按一次 START
> 即可恢复；正常比赛流程不受影响。

## 4. 屏工程清单（USART HMI 上位机）

这一节是"照着点"的步骤。屏是**独立的程序**，烧 STM32 不会改变屏上的画面；
屏工程只能在 USART HMI 上位机里做，再下载到屏。

### 4.1 新建工程

1. USART HMI →「文件 → 新建」。
2. 器件选 **TJC3224T132_011**；列表里没有就选分辨率 **320×240**、方向**横向**。
3. 工程名随意，例如 `task_display`。

### 4.2 波特率必须是 115200

在「工程设置 / 系统参数」里把波特率改成 **115200**（或直接改 `bauds` 属性）。
**这一项不对，屏和 STM32 一句话都说不上，而且没有任何报错。**

> 2026-10-17 起屏这一路从 9600 提到 115200（`BOARD_HMI_BAUD`），一页刷新从约 0.15 秒降到约 0.02 秒。
> 代价是对接线更敏感：屏的杜邦线尽量短、GND 必须可靠，最好和 STM32 共地且远离电机线。
> 若上板后返回码时有时无，先把两边一起降回 9600 排除线路问题。

### 4.3 建三个页面和控件

**第 0 页（任务码）**：放 2 个「文本 / Text」控件，`objname` 分别改成 `t0`、`t1`。

**第 1 页（统计）**：在右侧「页面」面板点 **+** 新建 page1，在 page1 上放 2 个文本控件，
`objname` 分别改成 `t2`、`t3`。

**第 2 页（启动页）**：再点 **+** 新建 page2，放 **1 个按钮**，`objname` 改成 `b0`，
按钮文字填 `START`（ASCII，不用 GB2312 字库），字库选 32 px。

```
page 0: t0    t1
page 1: t2    t3
page 2: b0（START 按钮）
```

**按钮的弹起事件**（不是按下事件）填两行：

```
printh 55 02 00 00 ff ff ff
page 0
```

第一行通知 STM32“START 已按下”，第二行让屏自己切到任务页。
这样即使串口暂时没通，按钮也能进任务页；串口通了固件会重刷任务文字。

大小写敏感，必须完全一致；不同页的控件名可以重复，但这里故意用不同名字方便调试。
**控件的位置、大小、对齐必须在上位机里设好**（见 4.3.1）：TJC 的 `x`/`y`/`w`/`h`
是只读属性，串口改不了；对齐用 `xcen`/`ycen`，`sta` 是字体渲染方式，不是对齐。
控件名不对时屏会回 `0x1A`，在 USART1 调试口能直接看到；
**发往另一页的指令也会回 `0x1A`**，这是分页最常见的问题。

#### 4.3.1 三个页面的控件坐标（在上位机里设）

| 页 | 控件 | x | y | w | h |
|---:|---|---:|---:|---:|---:|
| 0 | t0 | 0 | 52 | 320 | 64 |
| 0 | t1 | 0 | 124 | 320 | 64 |
| 1 | t2 | 0 | 76 | 320 | 40 |
| 1 | t3 | 0 | 124 | 320 | 40 |
| 2 | b0 | 60 | 80 | 200 | 80 |

启动页按钮可以是整屏大按钮，上表只是建议值；`b0` 的按钮文字在属性 `txt` 里填 `START`。

对齐在属性里把 **`xcen` 和 `ycen` 都设为“居中”**。**不要试图用 `t0.sta=1` 改对齐**：
`sta` 是单色/灰度字体渲染方式，写它会得到 `0x1C`。同理，`t0.x=0`、`t0.w=320`
这类指令全部是只读属性，固件已经不再发。

另外把 `t2`/`t3` 的 **`txt_maxl` 至少设成 16**：`PLACE OK 999` 是 13 个字符，
默认的 10 会把统计数字截掉。`t0`/`t1` 保持 10 就够（最长一行 8 个字符）。

### 4.4 建两个字库并套给控件

选中控件 → 属性里的「字体」→「...」→「字体生成」：

| 字库 | 字高（px） | 编码 | 套给 |
|---|---:|---|---|
| 现成字库 **ID 1** | **64** | ASCII | `t0`、`t1` |
| 现成字库 **ID 0** | **32** | ASCII | `t2`、`t3`、`b0` 的按钮文字 |

> 64 px 字体下 8 个字符约 282 px，320 px 宽放得下；不需要新建 59 px 字库。
> 如果工程里没有这两个字库，再按「字体生成」建：t0/t1 用 64（或 59）px，t2/t3 用 32 px，编码都选 ASCII。

⚠ 三个最常见的"屏上什么都没有"原因，都发生在这一步：

1. 控件建好了但**没套字库**；
2. 字色 `pco` 和背景色 `bco` 一样（有字但看不见）；
3. 字库编码选了 GB2312 却只想显示 ASCII（能显示，但字库更大；ASCII 足够）。

任务码和 `GRAB OK` / `PLACE OK` 全是 ASCII，**不需要 GB2312 字库**，
也不需要处理中文转码。

### 4.5 事件：只有 START 按钮有代码

`t0`～`t3` 的触摸/弹起事件、**三个页面**的页面加载事件**都留空**。
只有 `page 2` 的 `b0` 按钮在**弹起事件**里写两行：

```
printh 55 02 00 00 ff ff ff
page 0
```

除按钮外，这套显示是纯被动的：屏只执行 STM32 发来的指令，自己不往上发东西。
（屏执行指令后仍会自动回 `0x01` 状态码，这是正常且有用的。）

### 4.6 编译并下载

**方式一：串口下载（常规）**

1. 把屏从 STM32 上拔下，接 USB-TTL：屏 TX→适配器 RX、屏 RX→适配器 TX、**共地**，
   屏单独供 5 V。
2. 点「编译」生成 `.TFT`，再点「下载 / 联机下载」，选对 COM 口。
3. 下载期间屏上会显示进度条，**不要断电**。
4. 完成后把屏接回 STM32（PC6→屏 RX、PC7←屏 TX、GND、5V）。

**方式二：microSD 卡下载**

编译出的 `.TFT` 拷到卡根目录 → 插卡上电 → 自动刷入 → 拔卡、断电、重新上电。

### 4.7 先单独验屏（不接 STM32，推荐）

拿 USB-TTL 接屏，用 SSCOM（`资料\5.软件工具\串口助手SSCOM_v5.13.1.zip`）
在 **115200、十六进制发送**下发（前提是屏里已经下载了按 4.2 设成 115200 的新工程；
下载时的联机波特率由上位机自动协商，和运行波特率无关）。

**先验第 0 页（任务码）**：

| 发送（HEX） | 含义 | 通过判据 |
|---|---|---|
| `74 30 2E 74 78 74 3D 22 41 42 43 22 FF FF FF` | `t0.txt="ABC"` | `t0` 显示 `ABC`，回 `01 FF FF FF` |
| `74 31 2E 74 78 74 3D 22 44 45 46 22 FF FF FF` | `t1.txt="DEF"` | `t1` 显示 `DEF` |

**再切到第 1 页（统计）**：

| 发送（HEX） | 含义 | 通过判据 |
|---|---|---|
| `70 61 67 65 20 31 FF FF FF` | `page 1` | 屏切到统计页 |
| `74 32 2E 74 78 74 3D 22 47 52 41 42 20 4F 4B 20 33 22 FF FF FF` | `t2.txt="GRAB OK 3"` | `t2` 显示 `GRAB OK 3` |
| `74 33 2E 74 78 74 3D 22 50 4C 41 43 45 20 4F 4B 20 35 22 FF FF FF` | `t3.txt="PLACE OK 5"` | `t3` 显示 `PLACE OK 5` |
| `70 61 67 65 20 30 FF FF FF` | `page 0` | 回到任务页 |

**再验第 2 页（启动页）**：

| 操作 | 含义 | 通过判据 |
|---|---|---|
| `70 61 67 65 20 32 FF FF FF` | `page 2` | 屏切到启动页，看到 `START` 按钮 |
| 手动点一下按钮 | 触发弹起事件 | 屏切到 page 0，SSCOM 收到 `55 02 00 00 FF FF FF` |

这一步同时验证了按钮事件代码里的 `page 0` 和 `printh` 两行都执行了。

- 回 `1A FF FF FF` → 控件名不存在（检查 objname），**或者控件在另一页**（先发对应的 `page n`）。
- **什么都不回** → 波特率不是 115200，或 TX/RX 接反，或没共地。

这一步通过后，屏工程就不用再动了，后面全是 STM32 和 Pi 的事。

## 5. STM32 端

烧录 `MDK-ARM/Bench_Tests.uvprojx` 的 **`HMI`** Target（Rebuild 后确认下载的是
`MDK-ARM/Bench_Tests/HMI/HMI.hex`）。上电后 USART1 @115200 应看到：

```
TASK HMI ready: commands on USART3 115200, screen USART6 115200
TASK HMI: send TASK 156+123+516+231 / STAT 3 5 / PING on the command port
TASK HMI: waiting for START button on page 2
```

开机时固件切到 **page 2 启动页**，屏上只有一个 `START` 按钮。

按一下按钮后：

- 屏自己执行 `page 0`，切到任务页；
- 同时发出 `55 02 00 00 FF FF FF`，USART1 打印 `START button pressed`；
- 固件确认切到任务页并重刷文字，屏上显示 `NO TASK`。

如果串口暂时没通，按钮仍能把屏切到任务页（本地 `page 0` 生效），只是固件状态要等下一次
`TASK`/`STAT` 才同步。

命令来源由 `Tests/Src/hmi_smoke.c` 顶部的 **`HMI_COMMAND_PORT`** 决定：

- **`SERIAL_RPI`（USART3，默认）**：接树莓派，正式用法；
- **`SERIAL_DEBUG`（USART1）**：台架调试用，同一个口既看开机横幅又发命令，省一个 USB-TTL，改完要重新编译。

两者都是 115200 8N1，文本模式，**必须勾「发送新行」**（固件按 `\r`/`\n` 断行）。

在命令串口上发 `TASK 156+123+516+231` 后：

- 屏切到 page 0，第一行 `156+123`、第二行 `+516+231`；
- 命令串口回 `OK TASK`（默认 USART3）；
- USART1 打印 `TASK SET 156+123+516+231`；
- **USART1 上不应出现 `HMI return 0x..` 报错**（`0x01` 成功不打印）。

发 `STAT 3 5` 后：

- 屏切到 page 1，显示 `GRAB OK 3` / `PLACE OK 5`；
- 命令串口回 `OK STAT`，USART1 打印 `STAT grab=3 place=5`。

改 `Tests/Src/hmi_smoke.c` 顶部参数区可以调整控件名和刷新周期（布局在上位机里，改代码无效），
改完必须重新编译下载。当前固件每 5 秒刷新**当前页**（115200 下约 0.02 秒阻塞），
这个 Target 不驱动电机，所以可以接受；以后并进生产固件时必须和步进脉冲错开（AGENTS.md 第 6 节）。

## 6. 树莓派端

### 6.1 硬件接线（3.3 V 逻辑，不要接 5 V）

> 固件默认从 USART3 收命令。若临时改用 USART1 台架调试，把 `hmi_smoke.c` 的
> `HMI_COMMAND_PORT` 改成 `SERIAL_DEBUG`，重新编译烧录；接回树莓派前记得改回 `SERIAL_RPI`。

| 树莓派 | STM32 | 说明 |
|---|---|---|
| GPIO14 / TXD（物理脚 8） | **PC11 / USART3_RX** | Pi 发 → STM32 收 |
| GPIO15 / RXD（物理脚 10） | **PC10 / USART3_TX** | STM32 发 → Pi 收 |
| GND（物理脚 6/9/14…） | GND | **必须共地** |

TX/RX 是交叉的；Pi 与 STM32 都是 3.3 V，不需要电平转换。
`PINMAP.md` 里对这两个网络标注了"需核对收发交叉"，第一次接线务必用万用表/示波器确认。

### 6.2 打开树莓派串口

```bash
sudo raspi-config
# Interface Options -> Serial Port
#   "Would you like a login shell over serial?"      -> No
#   "Would you like the serial port hardware enabled?" -> Yes
sudo reboot
```

树莓派 3/4 默认把 PL011 给了蓝牙，`/dev/serial0` 会落到 mini UART（`ttyS0`）。
mini UART 的波特率跟 CPU 主频绑定，115200 也可能不稳。建议关掉蓝牙：

```bash
# /boot/firmware/config.txt（老系统是 /boot/config.txt）末尾加：
dtoverlay=disable-bt
sudo systemctl disable hciuart
sudo reboot
```

重启后 `ls -l /dev/serial0` 应指向 `ttyAMA0`。

把当前用户加入 dialout：

```bash
sudo usermod -aG dialout $USER
# 重新登录后生效
```

### 6.4 脚本用法

```bash
cd /path/to/Vehicle_BSP/Tools

# 0) 最常用：不带动作参数 = 用摄像头 0 连续扫码，识别到就上屏
python3 rpi_task_link.py --port /dev/serial0

# 1) 只看会发什么，不打开串口
python3 rpi_task_link.py --task 156+123+516+231 --dry-run

# 2) 手动发任务码
python3 rpi_task_link.py --port /dev/serial0 --task 156+123+516+231

# 3) 链路测试
python3 rpi_task_link.py --port /dev/serial0 --ping

# 4) 比赛结束发统计（抓取正确 3 次、放置正确 5 次）
python3 rpi_task_link.py --port /dev/serial0 --stat 3 5

# 5) 识别一张图片后下发
python3 rpi_task_link.py --port /dev/serial0 --image qr.jpg

# 6) 摄像头连续扫描，识别到第一个任务码后退出
python3 rpi_task_link.py --port /dev/serial0 --camera 0 --once
```

脚本会打印 `发送：...` 和 `STM32：OK TASK`；超时会提示检查接线/波特率/固件。

在 Thonny 里直接点「运行」不会带命令行参数，脚本会**默认打开摄像头 0 扫码**，
识别到合法任务码就通过串口发给 STM32 并上屏。没有摄像头时可以先用
`--image qr.jpg` 识别现成的二维码图片；想手动输入任务码就加 `--interactive`：

```
任务码> 156+123+516+231
任务码> stat 3 5
任务码> ping
任务码>
```

直接回车退出。带参数的一次性用法仍建议用终端（Thonny 菜单「工具 → 打开系统终端」）。

### 6.5 摄像头取码注意事项

- 二维码板 80×80 mm，摄像头距板 **10～30 cm** 比较稳；
- 避免逆光/反光，必要时给补光；
- 先用 `--image` 拍一张照片验证识别率，再上 `--camera`；
- 识别到合法任务码后按**任务码内容**去重：同一个码一直停在画面里、或偶尔丢帧/反光导致
  某几帧识别失败，都不会重复下发；只有识别到**不同的码**才再发一次。
- 若二维码内容带前缀（如 `TASK:156+...`），脚本用正则提取，不需要改代码。

## 7. 联调顺序（按这个顺序，故障好定位）

1. **屏单独验**：USB-TTL + SSCOM，按 4.7 先验 page 0 的 `t0`/`t1`，发 `page 1` 验 `t2`/`t3`，
   发 `page 2` 看点 START 按钮能否切回 page 0 并发出 `55 02 00 00 FF FF FF`。
2. **STM32 → 屏**：烧 `HMI` Target，USART1 看开机横幅和 `HMI return`，
   屏上应停在 **page 2 启动页**；按 START 后进入 page 0、显示 `NO TASK`。
3. **PC 模拟树莓派**：USB-TTL 接 USART3（PC11←适配器 TX、PC10→适配器 RX、GND），
   SSCOM 115200 文本模式、勾发送新行，发 `TASK 156+123+516+231`，屏应更新并回 `OK TASK`；
   再发 `STAT 3 5`，屏应切到 page 1。
   这一步把"屏"和"Pi"彻底分开排查。
4. **树莓派接上**：先 `--ping`，再 `--task`，最后 `--image`，最后 `--camera`。
5. **整流程**：扫码 → 上屏 → 比赛结束 `--stat` 更新统计。

## 8. 排查表

| 现象 | 最可能的原因 | 处理 |
|---|---|---|
| USART1 一条 `HMI return` 都没有 | 屏波特率不是 115200 / 屏 TX-RX 接反 / 没共地 / 屏没 5 V | 先按 4.7 单独验屏 |
| `HMI return 0x1A` | 控件名不对（`t0`～`t3` 不存在），或控件不在当前页 | 改 objname；确认 `STAT` 时屏已切到 page 1 |
| 发 `t2`/`t3` 一直回 `0x1A` | 屏还停在 page 0，指令只对当前页有效 | 先发 `page 1`（或让固件收到 `STAT` 自己切） |
| 屏中途重启后统计页不自动回来 | 屏回到 page 0，固件记录仍是 page 1 | 再发一次 `STAT`，会强制重新切页并刷新 |
| `HMI return 0x1C` | 发了只读属性（`t0.x/y/w/h`）或用 `sta` 当对齐 | TJC 的 x/y/w/h 只读、sta 是字体渲染；布局与 xcen/ycen 必须在上位机设，固件已不再发这类指令 |
| 有 `0x01` 返回但屏上没字 | 控件没套字库 / 字色=背景色 / 字库字号为 0 | 回到 4.4 检查 |
| 屏上只有部分控件更新 | 对应控件名不存在或字库缺失 | 看 USART1 返回码定位是哪个控件 |
| SSCOM 发 `TASK` 没回复、屏也不变 | 命令没发到 `HMI_COMMAND_PORT` 指向的口；默认是 **USART3** | 接树莓派就在 USART3 发；台架用 USART1 时把宏改成 `SERIAL_DEBUG` 并重编 |
| SSCOM 发 `TASK` 没回复（口对了） | 波特率不是 115200 / `HMI` Target 没烧进去 / 接线错 | 115200，确认 HEX 路径是 `Bench_Tests/HMI/HMI.hex`，查 TX/RX 与 GND |
| `ERR TASK FORMAT` | 任务码长度/字符不合法（含空格、全角字符） | 用脚本的 `--dry-run` 核对本地校验 |
| Pi 报 Permission denied | 用户不在 dialout 组 | `sudo usermod -aG dialout $USER` 后重新登录 |
| Pi 收到乱码或时好时坏 | mini UART 波特率漂移 / 蓝牙占用 PL011 | `dtoverlay=disable-bt`，确认 `/dev/serial0 -> ttyAMA0` |
| `--camera` 打不开 | 摄像头被占用 / CSI 未启用 / USB 摄像头编号不对 | `--camera 1`，或先 `--image` 验证 |
| 二维码识别不到 | 距离/对焦/反光/码太小 | 调整距离与补光；先拍照用 `--image` 试 |
| 下载报 `file is too large for destination device` | 工程文件超过屏的 4 MB Flash，常见原因是 GB2312 全字库/大图片/音视频 | 删掉 80/96 px 等不用的字库，字库编码改 ASCII、只勾需要的字符；删大图与音视频，重新编译到 4 MB 以下 |
| 按 START 没反应，屏停在启动页 | 事件写在“按下事件”或没下载；`b0` 不在 page 2 | 事件必须写在**弹起事件**里，重新编译下载；确认按钮在 page 2 |
| 按钮能切页，但 USART1 没有 `START button pressed` | `printh` 漏了结尾 `ff ff ff`，或写成了 `printh 55 02 00 00` | 补成 `printh 55 02 00 00 ff ff ff`；帧必须以 FF FF FF 结尾 |
| 开机不是启动页，直接显示任务页 | 烧的还是旧 HEX（启动页逻辑没编进去），或 USART6 没通 | 重编 `HMI` Target 并核对 HEX 路径；查 PC6/PC7 与屏 |

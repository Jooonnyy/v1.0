# 速度环调参与里程计

本次实现 `WHEEL` 台架入口与 App 层 `chassis_odom`。**代码已完成并编译通过，尚未上板验证，参数未标定。**
生产 `Vehicle_Integrated` 只初始化与周期更新里程计，上电仍保持四路 PWM 为 0、两片 TB6612 待机。
既有生产命令保持原有行为，本次没有新增运动命令或自动使能。

## 1. 台架入口与初态

在 `MDK-ARM/Bench_Tests.uvprojx` 选择 `WHEEL`，Define 为 `WHEEL_TEST`，产物
`MDK-ARM/Bench_Tests/WHEEL/WHEEL.hex`。入口只有 `main.c` 的分发链；测试没有独立 main。
启动顺序：急停、清编码器、打印静止提示、配置 IMU 并静止校准约 2 秒、归零位姿、开启遥测。
**校准时必须静止；启动过程不使能轮子。** 校准失败会报错，位置仍按编码器更新，但航向冻结，不能据此宣称定位有效。

参数位于 `Tests/Src/wheel_smoke.c` 顶部，后接编译期校验。默认遥测/文本口都是 `SERIAL_DEBUG`，
遥测频率 50 Hz，模式 0，命令缓存 48 字节（不含结束符最多 47 字符）。
遥测口只允许 `SERIAL_DEBUG` 或 `SERIAL_BT`；串口枚举使用 C99 类型长度校验，不能用预处理器把枚举名当宏比较。
文本口可以选任一有效串口，但 HMI 口要留给串口屏，不宜输出长状态行。
接 HC-05 时把遥测口改成 `SERIAL_BT`，文本仍留 `SERIAL_DEBUG`；两口都能收命令，各自缓存，半条命令不会跨口拼接。
每次 Poll 每口最多处理 64 字节，避免连续接收饿死里程计。

## 2. 命令表

大小写不敏感，空格/制表符分隔，CR、LF、CRLF 均可结束。解析完整消费参数；溢出、缺参、多参、非法字节和未知命令只报错，不产生运动。

| 命令 | 作用与范围 |
|---|---|
| `E 0` / `E 1` | 失能急停 / 显式使能。使能会清原目标，**先 E 1，再 V 或 B** |
| `V <a\|b\|c\|d> <counts_per_s>` | 单轮目标，±5000 counts/s；同时选择模式 0 的观测轮，默认 A。其他轮目标不变 |
| `B <vx> <vy> <wz>` | 整车目标，vx/vy 为 um/s，各限 ±1000000；wz 为 mdps，限 ±360000。BSP 再限每轮 ±5000 counts/s |
| `G` / `G <kp_q10> <ki_q10> <ff>` | 查询 / 设置生效增益；三个值均为 0..32767，固定回显 `GAINS kp=<n> ki=<n> ff=<n>`；Q10 除 1024。大增益不是调参建议 |
| `C` | 先急停并关闭遥测，提示 MUST remain STILL，再配置/校准约 2 秒。保留 x/y/heading，丢弃校准期间窗口与余数；之后手动 T 1、E 1 恢复 |
| `Z` | 编码器计数和位姿同时归零；不是急停命令，需要停车时先 STOP |
| `STOP` | 清目标、清积分、四路输出 0、两片 TB6612 待机 |
| `S` | 一行状态：四轮 target/actual/output、state、stalls、Kp/Ki/FF、位姿、速度、gyro_ready、zupt、pp_mdps、gyro_errors、resync |
| `T 0` / `T 1` | 关闭 / 开启遥测，不改变运动目标 |
| `?` | ASCII 英文帮助 |

`state=0/1/2` 分别为 IDLE/RUN/STALL。`gyro_ready=1` 仅表示当前读取、零偏和静止噪声门控可用，
不表示完成了实测标度；`zupt=1` 表示通过静止判定并抑制航向积分。
`pp_mdps` 是最近 20 次有效主循环读数的峰峰值，BSP 已有 8 点平均，所以**不能代替 MPU6050 专项的原始噪声实验**。
`resync` 是丢弃尖峰、长间隔或计数重置窗口的累计次数；`gyro_errors` 只统计 I2C 读失败。

**同口使用规则（2026-10-07 用户明确确认）**：启动提示在遥测开启前打印；普通 OK/ERR/S/G/帮助输出先暂停遥测，
整行文本发到 TEXT_PORT 后恢复原遥测状态。G 必须回显且恢复流，现有脚本不会在每次 G 后重新发 T 1。
T 1 的确认也在暂时暂停状态输出，后续恢复数字流。S 长状态行可能暂时降低主循环更新率；看状态时建议 T 0。
**STALL 与 C 先关闭遥测并保持关闭**，提示可见，之后手动 T 1 恢复；运动仍需显式 E 1。
这按照用户对同口冲突的确认处理：同一根 UART 上数字流和文本分时，波形段仍只有数字行；
严格纯数字接收器应将遥测切 BT、文本留 DEBUG。现有 wheel_tune.py 会忽略普通非数字行，并在同口看到 STALL 时终止。

自动调参硬契约：V 设置目标且立即选择同一路遥测；未发 V 时默认 A；模式 0 每行严格三列整数。
STOP 在失能、运行、STALL、关闭遥测时都直接调用 Wheel_Stop，连续三次也有效。
TIM7 堵转已急停后，主循环根据堵转累计事件打印 `STALL: wheels stopped; explicit E 1 required`，
不在中断里发串口，不依赖可能被 STOP 清掉的 state。G 的唯一查询/设置回显例如 `GAINS kp=200 ki=8 ff=136`。

## 2.1 最简调试流程：`X` 与 `D`（2026-10-07 追加）

为了不刷屏、不用上位机也能调参，加了两条命令。**默认不再自动发遥测流**（要波形才 `T 1`）。

| 命令 | 作用 |
|---|---|
| `X <a\|b\|c\|d> <counts/s> [ms]` | **闭环阶跃测试**：给目标 → 按 2 ms 采样实际转速 → 到时自动停该路 → 只回**一行**摘要 |
| `D <a\|b\|c\|d> <permille>` | **开环**直接给占空比，**不看编码器**；会先关闭环（`E 1` 恢复），用来分清"电机/驱动/动力电"还是"编码器反馈" |

`X` 的回显格式与判读（示例）：

```text
X a 1500: peak=1620 over=8% rise=190ms steady=1502 err=2 osc_pp=34 duty=204 tail=64
```

| 字段 | 含义 | 调参动作 |
|---|---|---|
| `over` | 超调百分比 | 偏大或 `osc_pp` 大 → 减 Kp |
| `rise` | 10%→90% 上升时间，ms | 偏慢 → 加 Kp |
| `steady` / `err` | 末尾窗口均值 / 与目标的差 | `err` 不为 0 → 加 Ki |
| `osc_pp` | 末尾窗口峰峰值 | 低频摆动 → 减 Ki |
| `duty` | 结束时的占空比 | 标定前馈：`ff ≈ 1000 × duty ÷ steady` |

标定顺序：先 `G 0 0 <ff>` 只留前馈把 `steady` 调到≈目标 → 再加 Kp 压 `over`/`rise` → 最后加 Ki 消 `err` → 四轮各跑一次 `X` → `S` 或 `B` 验整机方向。

**闭环缺反馈时必然判堵转**：编码器没信号 → 误差恒在 → 积分顶到限幅 600‰ → 0.6 s 后急停并打印
`STALL`。所以看到 `X ... peak=0 steady=0` + `STALL`，先怀疑"电机没转"或"编码器没反馈"，
**不要先怀疑 PI 参数**；用 `D a 500` 一步就能分开这两种情况。

## 2.2 纯开环电机台架：`ALL` / `CMP` / `N`（2026-10-26 追加）

`D` 只能手动一路一路给，比较四路电机要来回敲；这组命令把"拆掉联轴器后比电机"做成一条命令。
**它们都先 `Wheel_Enable(0)` 关闭环**，所以读数不经过 PI / 积分 / 限幅，只反映电机、驱动、动力电这一段。

| 命令 | 作用 |
|---|---|
| `ALL [permille]` | 四路一起开环；省略参数按 `WHEEL_SMOKE_OL_PERMILLE_DEF`（300），`ALL 0` 全停。上限与 `D` 相同（`WHEEL_SMOKE_DIRECT_PERMILLE`）。 |
| `D <a\|b\|c\|d> <permille>` | 单路开环（原有命令；现在同时记进 `S` 与遥测的开环字段）。 |
| `CMP [permille] [ms]` | 四路**依次**开环，每路取末尾 500 ms 的平均转速，结束时回一行：`CMP 300 permille: A=2130 B=2050 C=840 D=2180 counts/s` |
| `N` | 打印四路累计计数：`COUNTS A=... B=...`。手转减速箱输出轴一圈应接近 `WHEEL_COUNTS_PER_REV`（1320）。 |

- 开环期间**任何命令都会中止 `CMP` 并把四路清零**；`STOP` / `E 1` 同样退出开环。
- 开环输出非零、且 `WHEEL_SMOKE_OL_IDLE_STOP_MS`（默认 60 s）内没有命令 → 自动全停并打印
  `OL idle timeout, all outputs off`，防止忘记关。
- 参数区：`WHEEL_SMOKE_OL_PERMILLE_DEF` / `_CMP_MS_DEF` / `_CMP_MS_MIN` / `_CMP_MS_MAX` /
  `_TAIL_MS` / `_IDLE_STOP_MS`，全部有 `#error` 校验。
- **遥测模式 2 的第三列**在开环时改为发**指令占空比**（否则 `Wheel_OutputPermille()` 恒为 0，
  看波形会以为没输出）；`S` 新增 `ol_mode=` 与 `ol_permille=a/b/c/d`。
- 判据（空载、1320 counts/rev）：`CMP 300` 实测 **1522~1869 counts/s**（2026-10-26；电池电压低时会更小），
  四路极差约 19% 以内算正常；某一路明显低，就是那一路的电机 / 减速箱 / 线路 / 编码器。

## 2.3 航向保持（`O` / `K` / `J`）的开法

顺序不能反 —— `O 1` 用的是**最近一次 `B` 记下的基础速度**（base vx/vy），
而且 2026-10-26 之前 `E 1` 会误杀保持（已修：现在只有 `E 0` 取消）。

```text
TM 3            # 先确认陀螺仪在出数：age_ms < 200、frames 在涨；Y 里的 period_ms 是帧间隔
E 1             # 使能（不再取消保持）
B 300000 0 0    # 先给基础速度：0.3 m/s 直行，同时记下 base vx/vy
O 1             # 以当前 yaw 为目标开始保持
K 4 / J 1       # 在线调参（静默，专给 VOFA+ 滑块）
O 0             # 关闭；STOP 也会关闭
```

- 每 10 ms 修正一次，死区 300 mdeg，`wz` 限幅 80°/s；**500 ms 没有新帧会自动退出保持**。
- `B` 可以在保持中改速度（不取消）；`V/W/D/X/M/STOP` 会取消保持。
- 符号反了改 `WHEEL_SMOKE_YAW_SIGN`，不要靠翻转 Kp 的正负。
- 陀螺仪只有 ~10 Hz（`period_ms` ≈ 100）时，航向环的反馈最多滞后 100 ms，
  这是环路带宽的主要瓶颈；要更快得先把模块输出率调到 100/200 Hz。

## 2.4 里程计与点到点导航（`R` / `GO`）—— 2026-10-26 追加，未编译验证

只用编码器 + HWT101，不依赖 MPU6050（新板已经拆掉 MPU）。
`odom_poll()` 每 10 ms 用四路编码器线速度做逆运动学反解并积分位置，
航向取 HWT101 的相对角（`R` 时把当时的原始 yaw 记成零点）。

- **2026-10-27 补**：车体位移（vx/vy）现在按**当前航向旋转进场地系**再积分
  （`odom_rotate_integrate()`，Q15 四分之一波表 91 项 + 插值，无浮点）。
  之前只在"航向恒 0"时成立，分段换航向必然算错位置——这是跑一圈的前提修复。
  两级余数（vx·dt 的 /1000、旋转乘积的 /32768）都跨拍保留防截断。
  正式量产的位姿积分仍应走 App 的 `chassis_odom`（257 项 Q8 插值 + 中点旋转），本处只是台架版。

```text
R                       # 复位：当前位置=原点、当前航向=0（上电/换场地后必须先发）
GO 300 0                # 走到 x=300 mm, y=0，航向保持 0
GO 0 400 90             # 走到 (0,400)，最终航向 90°
S                       # pose_mm=x/y/heading，goto=是否在走，dist_mm=剩余距离
TM 4                    # 遥测：x_mm,y_mm,heading_mdeg,goto,dist_mm,vx_mm_s,vy_mm_s
```

- 控制律：航向稳定在 0 时车体系 ≈ 场地系，直接 `vx = Kp·ex`、`vy = Kp·ey`（麦轮可横移），
  `wz = Khead·航向误差`；离目标 <120 mm 降到慢速，<15 mm 判定到点。
- 航向差 >30° 时先原地转，不走；单段超时 30 s 自动全停；
  **陀螺仪掉线立即停**并回 `GOAL aborted: gyro frames lost`（不再带着冻结的航向继续走）。
- 参数在 `WHEEL_SMOKE_GOTO_*` / `WHEEL_SMOKE_ODOM_PERIOD_MS`，都有 `#error` 校验。
- ⚠ **盲走**：没有任何障碍检测，发 `GO` 之前确认路径上没人没东西。
- ⚠ 精度受轮径标定与陀螺仪零漂限制，预期 **±3~5 cm**，只够"开到区前"，不够放进圆环。

## 2.5 原地转（`A`）与正方形跑一圈（`LAP`）—— 2026-10-27 追加，已编译未上板

### `A <±deg>` 闭环原地转到相对角度

```text
E 1
A 90          # 左转 90（车体逆时针为正），到位后自动全停
A -90         # 右转 90
S             # turn=1 err_mdeg=... lap=0 leg=...（新增字段）
```

- 航向环就是 `heading_poll()` 的 P+I+死区+限幅（Kp/Ki 用 `K`/`J` 在线调），
  `A` 只负责"设目标（当前 yaw + Δ·YAW_SIGN）、盯到位、超时收工"。
- 完成语义：**连续 400 ms 内 |误差| ≤ 2° 且角速度 ≤ 15 deg/s** → 全停并回一行摘要
  （`TURN done err_mdeg=... ms=...`）；整段超时 12 s 或陀螺仪掉线 → `TURN timeout/abort`。
- 实现是轮询判定（非中断），主循环单拍卡顿最多多计 20 ms，不会虚判到位。
- 完成后航向保持一并关掉；需要继续定航直行就再发 `O 1` 或用 `GO ... <heading>`。
- 任何运动/初始化命令（`B/V/W/D/E/X/M/Z/R/GO/A/LAP/STOP`）都会中止正在跑的 `A`。

### `LAP [side_mm]` 正方形跑一圈

```text
R             # 先复位：当前位置=原点、航向=0（⚠ R 不带参数，写 R 1000 会回 ERR 且不复位）
LAP 1000      # 以当前位置为起点跑边长 1 m 的正方形，逆时针（不填默认也是 1000）
```

- 四个航点在 `LAP` 时算好：`(x+S,y,0°) → (x+S,y+S,90°) → (x,y+S,180°) → (x,y,−90°)`，
  每段**"先原地转正到段航向、再纯直行"**（`WHEEL_SMOKE_GOTO_TURN_FIRST_MDEG=30°` 生效），
  **不用横移**——横移当前另有问题（只有两轮动、走斜线）在排查，别用它给 LAP 背锅。
- 段间结算靠 `goto_state.result`：到点=接续下一段；任一段超时 30 s / 被 STOP →
  `LAP aborted at leg N`，整圈作废；全程完成回 `LAP done ... final_mm=...`。
- 收尾精度对 odom 位置（±3~5 cm 一级的"开回原点"），绕一圈的累计误差自己看
  `final_mm` 判断里程计闭合质量；**没有障碍检测，全场空旷才发 `LAP`**。
- 边长合法范围 300..3000 mm，默认 1000。参数 `WHEEL_SMOKE_TURN_*` / `WHEEL_SMOKE_LAP_*` 都有 `#error` 校验。

### HWT101 现状评估（2026-10-27 盘点）

已用上的：`0x53` 角度帧的 yaw（唯一航向源，帧校验严格 + 出数率监测 `period_ms`）、
帧差分角速度（只作遥测/到位判定）、P+I 航向保持、`GO` 航向控制、`Y`/`TM 3` 观测。

**尚未利用、值得利用的**：

1. **`0x51` 角速度帧没解析**：现在角速度是 yaw 差分，10 Hz 下量化粗、掉一帧就出错。
   解出 `0x51`（0.05 °/s 单位计数 `gyroL gyroH`）可以直接拿真实 ω，让 `A` 的到位判定
   和航向环微分更好；改动只在 `hwt_poll()` 加一个分支。
2. **维特协议配置命令**（帧结构 `FF AA XX VV + SUM`，先模块解锁 `FF AA 69 88 B5`）：
   yaw 回零 `FF AA 76 00 00`（省掉每次 `R` 前的相对角换算）、输出速率调高
   （10 Hz 对一圈"转正判到位"偏粗，建议提到 100 Hz 以上，配套改 USART 收容）。
   需要实板用串口工具先逐条试通再写进固件。
3. **HWT101 没有磁力计**（单维陀螺仪），yaw 永远是相对角：长时间跑圈有慢漂，
   `A`/`GO` 每次开始都以"当时 yaw"为基准重新记目标，所以单段内不受影响；
   整场定位靠"开始前 `R`"并在必要时周期性复位，或走第 2 条的 yaw 回零命令。
4. 模块还能输出加速度/姿态四元数/温度帧——目前没有任何需求要用上。

## 3. VOFA+ 遥测与单位

115200、8N1、FireWater。每行仅整数、逗号和 LF，主循环拼完整行后只调用一次 Serial_Write；
周期路径不用 printf/snprint/浮点。默认格式由 `WHEEL_SMOKE_TELEMETRY_MODE` 决定，
**运行时可以用 `TM <0|1|2|3>` 切换**；非法值在编译期报错。

| 模式 | 通道顺序 | 上位机换算 |
|---|---|---|
| 0 | `tgt_cps,act_cps,out_permille` | 前两个为 counts/s；输出除 10 为占空比百分数 |
| 1 | `x_um,y_um,heading_mdeg,vx_um_per_s,vy_um_per_s,wz_mdps,t_ms` | x/y、vx/vy 除 1000 为 mm、mm/s；角度与角速度除 1000 为 °、°/s |
| 2（默认） | 四轮 `tgt_cps,act_cps,out_permille` ×4（12 通道） | 同模式 0；开环时第三列发**指令占空比** |
| 3 | `yaw_mdeg,yaw_rate_mdps,age_ms,frames,bad` | 前两个除 1000 为 °、°/s；`age_ms` 是最后一帧距现在的毫秒数，>200 基本就是掉线 |
| 4 | `x_mm,y_mm,heading_mdeg,goto,dist_mm,vx_mm_s,vy_mm_s` | 里程计位姿与导航状态；`goto` 1 = 正在走，`dist_mm` 是到目标的剩余距离 |

模式 0 目标为上层命令目标，不是软启动后的内部 ramp。轮速换算使用实测后的 CPR 与有效轮径；
当前占位约 0.1785 mm/count，不可当作实测比例。
模式 1 时间戳为该位姿对应编码器窗口的采样时间。主循环实际窗口 Δt 用于速度与航向积分，不假定每次正好 10 ms。
115200 有效吞吐约 11520 B/s：三通道上限约 30 B/帧，七通道极限约 84 B/帧；
50 Hz 分别约 1.5/4.2 kB/s。200 Hz 的七通道极限已超带宽，1..200 的合法参数范围**不代表串口能跑满**。
长状态行或 I2C 会延迟主循环，定时闭环仍在 TIM7；遥测不补发积压帧。

## 4. 分层、窗口与定点实现

- BSP `board_encoder` 是唯一计数采样点。TIM7 按既有 100 Hz 采样与控制，新增 volatile 编码器窗口仅累计增量、单拍最大计数增量、拍数、时间戳和重置代号；没有 I2C、三角函数或串口。
- `Encoder_TakeWindow` 在短临界区搬走窗口并清累计量，只允许里程计这个单消费者调用。原有 Encoder_Counts/Speed 接口保持无副作用。重置代号避免 ResetAll 被误认为巨大的反向移动。
- App 通过 BSP 的时基和临界区包装取时间/快照，新增算法代码不直接调用 HAL、CMSIS 或寄存器。位姿写入与复制均在短临界区，无忙等 seqlock。
- 车轮位移按 `Δcounts × effective_circumference / CPR`，int64 中间值并保留除法余数。几何和角映射复用 `board_wheel.h`；ODOM_SIGN_WHEEL 是编码器已归一化后的额外修正，默认 +1，不要重复反转。
- 正解：`dx=(FL+FR+RL+RR)/4`，`dy=(-FL+FR+RL-RR)/4`，`spin=(-FL+FR-RL+RR)/4`。与逆解反代分别得 4vx、4vy、4Lω，保留除四余数；编码器角速度只作诊断，不自动替代故障陀螺仪。
- 默认陀螺仪定航向：符号/千分比修正、150 mdps 死区、轮速与每拍计数峰值判静止、20 读数噪声窗口、连续 200 ms 静止后 ZUPT。阈值全部待台架实测。
- 轮子静止且最近 20 读数 pp 超 1000 mdps 时，拒绝该航向窗口并置 gyro_ready=0；不使用旧角速度填补 I2C 失败；C 配置/校准失败时显式禁用航向，不沿用驱动可能保留的旧零偏。**车轮无计数时的真实外部旋转可能被噪声门控屏蔽**，需实板验证阈值，不能将现有 10–15 dps 噪声宣称修好了。
- 航向用 `mdps×Δt_ms` 余数累加，归一化到 `[-180000,180000)`；中点航向旋转局部位移。Q15 四分之一波表 257 项、514 B，象限折叠与 Q8 插值，int64 乘法；旋转除法也保留余数。int16 正端点为 32767，带来约 31 ppm 标度误差，远小于未标定轮径与打滑误差。x/y 超 int32 范围饱和，不回绕。
- 参数超过 12 项，按规范放 `chassis_odom_config.h`，API 头 include 它。几何直接使用 BSP 已校验的同名值，避免两个层各维护一份。
- `ODOM_USE_GYRO=0` 仅用于编码器算法隔离验证；此模式 gyro=0，航向来自编码器正解；正常固件为 1，不会在传感器故障时自动切换。

**尖峰与长阻塞**：默认单个 TIM7 拍的车轮位移超过 `ODOM_RESYNC_MAX_UM=3000` 就丢弃整个待处理窗口；
保留单拍峰值，防止累计窗口中正反尖峰互相抵消。超过 `ODOM_MAX_GAP_MS=100` 也丢弃并重同步，无法恢复这段真实位移。
3000 um/10 ms 在当前参数下最多约 **16 counts/拍（约 1600 counts/s）**；17 counts 即拒绝，连续标度边界约 1680 counts/s。
因此允许 V 5000 不等于里程计能接受该速度。台架低速先测；高速前需按实际速度、采样周期与噪声据实调整阈值。
设计稿 3.5 的“4000 counts/s 时约 2000 um/拍”算术有误：当前标度实际约 **7140 um/拍**。

## 5. 标定顺序（对照设计稿第 4 节）

先架空并确保编码器供电、共地。**2026-10-27 已实测并写死：轮径 70 mm、前后轮心距 220 mm、
左右轮距 230 mm（半轴距/半轮距 = 110000/115000 um）**；其余仍无实测的项保持占位值
（CPR=1320、角映射恒等、各符号 +1、Kp/Ki=200/8、FF=136），不凭估算回填。
**动力电池为 12 V 锂电池（2026-10-07 用户确认）**，FF=136 保持不动。
1320 counts/rev÷60=22 (counts/s)/rpm；空载 333 rpm→7326 counts/s；
`1000 permille÷7326×1000≈136 permille per 1000 counts/s`。
空载实测 FF 130–160、带载（驱动压降与滚阻）150–175 只供体检；
最终以 `FF=1000×实测稳态占空比/实测转速` 自洽计算，不能拿预期区间凑结果。

| 12 V 与当前占位几何的参考量 | 值 |
|---|---:|
| 每米计数 | 约 5602 counts/m |
| 空载最高速 | 7326 counts/s，约 1.31 m/s |
| 600 permille 限幅下参考最高速 | 约 4400 counts/s，约 0.78 m/s，实际带载需测 |
| 1 m/s 对应计数率 | 5602 counts/s |

WHEEL_DUTY_LIMIT_PERMILLE=600、WHEEL_TARGET_LIMIT_CPS=5000、WHEEL_INTEGRAL_LIMIT_PERMILLE=300 全部保持。

| 7 陀螺仪标度 | 标记起始角，先逆时针准确转一整圈；再转 10 圈复测 | 用解包航向对照 360000/3600000 mdeg，单圈误差 <3°、十圈比例误差 <3%；改 GYRO_Z_SIGN 和 GYRO_SCALE_PERMILLE=旧值×真值/积分值 |

航向遥测会在 ±180° 回绕。上位机相邻差先折叠到 ±180000 再累计，**不能拿整圈结束的归一化角直接当 360° 标度读数**。
先完成七项，再闭合路径：前 1 m、左 1 m、后 1 m、右 1 m，目标回起点位置 <10 cm、航向 <5°；带载重测并记录打滑。

速度环使用现有 `Tools/wheel_tune.py`，**不改写脚本、不在固件里自动扫增益**。
先架空、确认极性与编码器，再执行：

```text
python Tools/wheel_tune.py --selftest
python Tools/wheel_tune.py --list
python Tools/wheel_tune.py --port COM5 --wheel a --target 1500
```

COM5 替换为实际端口；同一 COM 不要同时开 VOFA+。流程严格为 **前馈 → Kp → Ki**，脚本自己按时间窗采样，
固件命令不等待电机到位，除 C 外不调用 HAL_Delay。Serial_Write 是现有阻塞式板级发送，文本/遥测仍在主循环完成。
脚本最后打印三行宏定义，**在线改的增益只在 RAM，复位 / 重新烧录即丢失，最终值必须写回 `board_wheel.h`**。
随后重新编译烧录，明确参数与测试记录对应，再复测。FF 是每 1000 counts/s 所需 permille。
极性和测速可靠前不要开始 PI 调参；输出上限始终保持 600 permille，不靠提高上限追目标。
G 的在线参数仅存 RAM，复位恢复 BSP 默认，确定后人工回填参数区。

## 6. 常见问题

| 现象 | 排查 |
|---|---|
| S/?/G 没回显 | 核对 TEXT_PORT 接线；同口现会暂停后回显，可 T 0 降低刷屏；分口时文字不会出现在遥测线 |
| 不转 | E 1 后再下目标；STOP/C 会失能；确认供电、STBY、编码器、电机符号和 stall 状态 |
| 某轮 actual=0 | ENCODER 先看 tick 与计数；不把缺供电当 PI 参数问题 |
| 有轮速但 x/y 不动 | S 看 resync；默认阈值已由 3000 um 提到 **15000 um/拍**（=1.5 m/s/轮，高于 12V 空载 1.31 m/s）。仍频繁 resync 就查编码器毛刺与打滑 |
| `X` 回 `peak=0 steady=0` + `STALL` | 闭环没有反馈：要么电机没动（动力电/STBY/插头），要么编码器没信号。先 `D <轮> 500` 开环试，再分别查 |
| 航向不动 | 先看 gyro_ready、gyro_errors、pp、bias；静止 ZUPT 正常；读失败或静止噪声超限会冻结 |
| 航向慢、拐弯延迟 | 原驱动 8 点平均约 80 ms 窗口，叠加软件 I2C/发送延迟；先测相位与噪声，再决定滤波，不以噪声掩盖真实转动 |
| C 后位置跳/车突然转 | C 应先急停且校准后仍失能；窗口已重同步。实板确认 UART 队列、提示与机械惯性，校准时绝不能手推 |
| 高速七通道跟不上 | 降频，检查波特率/HC-05；周期不得靠补发积压帧追赶 |

## 7. 与设计稿的明确调整

1. 服从 AGENTS.md：超过十二项参数拆配置头，BSP 不 include App；用 BSP 时基/临界区包装维护依赖。
2. 默认同口与纯数字/脚本 STALL 回显契约冲突，用户明确确认分时暂停方案：普通回显暂停后恢复，STALL/C 停流后提示；严格纯数字需分口。这是用户授权对原“同口只数字”的具体调整。
3. 修正 Q8 表索引为 `angle_mdeg×65536/90000`；设计的 ×256 少了 8 位小数。查表端点、插值乘法加括号，避免原伪码移位优先级歧义。没有声称该整数插值误差严格 <1 LSB。
4. 单拍尖峰阈值保留 3000，但按 TIM7 单拍峰值判断；累计多拍不会仅因主循环晚了 10 ms 被误判。新增 100 ms 间隔丢弃保护与故障诊断。

6. 原始设计稿的轮径 60 mm、半轴距/半轮距已确认值等历史矛盾不作为实现依据。所有标度仍待实测。

**2026-10-27 停机改成主动刹车（改完待编译）**

原行为：`Wheel_Stop()` → `Motor_StopAll()` → `Motor_Set(id, 0)` →
`IN1=0、IN2=0`，电机两端悬空，**纯滑行**。0.5 m/s 要将近 1 s 才停，停不准，还会"自己往前蹭一段"。

新行为：`Motor_Brake()` 把 `IN1=1、IN2=1`（IN2 恒高），电机绕组被短接形成**动态制动**；
`Wheel_Stop()` 先刹车 `WHEEL_BRAKE_MS = 150` ms，再由 `Wheel_Update()` 的计时器松开成滑行。

- 新增 API：`Motor_Brake()` / `Motor_BrakeAll()`（`board_motion.c`）、
  `Wheel_IsBraking()` / `Wheel_BrakeCancel()`（`board_wheel.c`）。
- **踩到的坑**：`STOP` 和 `E 0` 后面紧跟 `ol_off()`，它内部会 `Motor_StopAll()`，
  正好把刚上的刹车变回滑行。现在 `ol_off()` 先查 `Wheel_IsBraking()`，刹车窗口内不再 StopAll。
  同理 `D` / `ALL` / `CMP` / 上电自检这些**开环**路径必须先 `Wheel_BrakeCancel()`，
  否则刹车计时器到点会把开环占空比清零。
- ⚠ 风险：动态制动是电气刹车，减速时电流灌回电源；麦轮高速急刹容易瞬间失抓、可能甩尾。

**2026-10-27 横向移动 + TASK 流程封装（改完待编译）**

### 左右横移：`ML <mm> [speed]` / `MR <mm> [speed]`

横移复用了 `M` 的定距离状态机，只多了一个轴向：

- `M` / `ML` / `MR` 共用 `move_start_axis(distance, speed, axis)`，`axis` 决定最后发的是
  `Wheel_SetBodyVelocity(vx,0,0)` 还是 `(0,vy,0)`。
- **横移的距离不能用四轮平均**——横移时四轮两两反向转，平均值恒为 0。改用侧向反解：
  `vy = (-FL + FR + RL - RR)/4`，代码里就是 `(-ΔA + ΔB + ΔC - ΔD)/4`，
  与 `Wheel_SetBodyVelocity()` 的 X 型解算严格互逆。
- `ML` 正数 = 左移，`MR` 正数 = 右移（内部对 `MR` 取负），命令里不用写符号。
- ⚠ 横移方向对不对，用 `B 0 300000 0` 先眼看一下：四轮都应该转，车向**左**平移。
  只有两轮转、走斜线，说明轮子装向或 `WHEEL_LATERAL_SIGN` 不对，先查那个再谈精度。

### 流程封装：`TASK`

把一整条路径写成一张步骤表，一条命令顺序跑完：

```c
static const TaskStep task_steps[] = {      /* wheel_smoke.c */
  {WHEEL_SMOKE_TASK_FWD,  400},
  {WHEEL_SMOKE_TASK_TURN,  90},
  ...
};
```

- 步骤类型：`FWD` / `BACK`（mm）、`LEFT` / `RIGHT`（mm，横移）、`TURN`（deg）、`WAIT`（ms）。
- **速度**：直线段用 `WHEEL_SMOKE_TASK_SPEED_UM_PER_S = 600000`（0.6 m/s，对应手动发
  `B 600000 0 0`；2026-10-29 由 400000 提高，用户要求加快前进）；
  横移段用 `WHEEL_SMOKE_TASK_STRAFE_UM_PER_S = 300000`（0.3 m/s，2026-10-28 提高），
  因为麦轮横移效率只有正向的一半左右，再快四路容易一起顶到 600‰ 限幅。
  600000 um/s 折合每轮约 **2063 counts/s**（810 计数/转、轮径 75 mm；满速约 4495），
  按前馈口径 125‰/1000cps + 摩擦项 70‰ 估稳态占空比约 330‰，弱的那一路约 380~420‰，
  离 `WHEEL_DUTY_LIMIT_PERMILLE`(600) 仍有余量；再往上加之前必须先看四路 `output` 实测值。
- **减速段（2026-10-29 改）**：`WHEEL_SMOKE_MOVE_SLOW_MM` 只有 40 mm 是按 0.4 m/s 标定的，
  0.6 m/s 下 40 mm 来不及从 0.6 降到 0.06，必然冲过头；而走廊净宽 400、车 300，
  余量只有 ±50 mm。所以减速段改成**按巡航速度等比缩放**，两个量一起动：

  | 量 | 0.4 m/s | 0.6 m/s | 缩放律 |
  |---|---|---|---|
  | `move.slow_mm`（减速距离） | 40 mm | **90 mm** | `WHEEL_SMOKE_MOVE_SLOW_MM × (v/400000)²`（封顶 300） |
  | `move.slow_speed_um_per_s`（进场速度） | 0.06 m/s | **0.09 m/s** | `WHEEL_SMOKE_MOVE_SLOW_SPEED_UM_PER_S × (v/400000)` |

  距离按 v²、速度按 v ⇒ 整个停车过程就是 0.4 m/s 那套的等比放大，毫米级裕量不变。
  **两个量必须一起放大**：只放大距离的话末段要爬 90 mm / 0.06 = 1.5 s，
  13 段直线合计多花约 20 s —— 比提速省下的时间还多，等于白提。
  参考速度 400000 及以下两个量都用原值，所以 `M` 默认 0.15 m/s、横移 0.3 m/s 的行为不变。
  `MOVE start` 回显末尾多了 `slow_mm=` 与 `slow_um_per_s=`，可直接核对本段的减速参数。
  仍停不准时优先抬 `WHEEL_SMOKE_MOVE_SLOW_SPEED_UM_PER_S` 的基准值，别再动速度常量。
- 调度：`task_poll()` 只看 `move.active` / `turn_active`，谁在跑就等谁；段间结算不依赖陀螺仪，
  所以**不需要 `R`、不需要里程计**——这正是当前阶段要的。
- 每段直线开始前自动打开航向保持（`task_hold_heading()`，目标取当前 yaw），
  因为一次 `turn` 结束后 `heading_hold` 会被清掉，不重开会漂。
- 中止：`STOP`、任何运动命令（`B/V/W/D/E/X/M/Z/R/A/L/GO`）、堵转，都会清 `task.active` 并停下；
  某一步启动失败（例如没陀螺仪帧）会回 `TASK aborted at step N: ...`。
- 回显：`TASK start steps=8` → `TASK step 3/8` → `TASK done steps=8 pose_mm=x/y`。

**为什么按"表驱动"封**：后面要加里程计约束时，只需要在某一步里补"到点后校验 `pose`、
超差就补一段修正"，调度本身不用动。现在这套是纯编码器距离 + 陀螺仪转角，是"任务跑图"的骨架。

**验证状态**：未编译、未上板。判据：`TASK` 能从头跑到 `TASK done`，四段直线和四个 90° 转向都执行；

**2026-10-27 原地转向"跑位置"（用户提出，改完待编译）**

现象：`A <deg>` 能把角度转到位（`err_mdeg` 几百），但车身位置会平移，不是纯绕中心。

- **瞬时段（代码可改善）**：`heading_poll()` 里 `wz = error × Kp`，90° 的误差直接乘成 360 °/s，

  ⚠ 前提是编码器符号正确、`pose_mm` 真的能反映平移 —— 也就是上面那个未解决的符号/标度问题。
  在 `pose_mm` 可信之前做位置闭环，等于拿错的反馈去修正，会更糟。

**新增观测**：`TURN done` / `TURN timeout` 末尾加了 `drift_mm=<dx>,<dy>`，

### 误差分解（全部来自本次日志）

| 来源 | 证据 | 量级 |
|---|---|---|
| 横移横向溜车 | 各横移段 `side_mm`：900 mm 段 3~9、1850 段 26/27、1950 段 35（约 1.5~1.8%）；方向正负都出现（10 段里 9 负 1 正），**不能固定补偿** | 账面合计约 (−35,−35) mm |
| 转身角残差 | 6 个 `TURN_ABS` 里 4 个带 ±1.0~1.2° 收工（旧到位阈 2000 mdeg 太松）；1° 残差让随后的 900~1950 mm 段整体偏转，端点差 = 段长×sin(残差) ≈ 16~34 mm/段 | 与上一项同量级 |

| 停车滑行溜车 | 各段账面合计与 closure 的缺口 ~60 mm：`Wheel_Stop` 断电后"刹车 150 ms + 滑行"阶段溜出去，横移方向车体沿滚轴自由滑、溜得最远；**不进任何单段打印，只进总闭合差** | 隐性大头 |

### 四项修正（当日完成，已编译 0 错 0 警）

1. **转身到位阈收紧**：`WHEEL_SMOKE_TURN_TOL_MDEG` 2000 → **500**。
   航向环死区 300 mdeg 之上留余量，P 项能把末段收敛进来；残差 1.2° → ≤0.5°，
   段旋转端点差同比缩到 1/3 以下。代价：每次转身收尾多几百 ms。
2. **横移横向位置环**（新）：横移全程用 odom 每拍反馈垂直偏移
   `move_cross_offset_um()`，按 `WHEEL_SMOKE_STRAFE_CROSS_GAIN_UM_PER_S_PER_MM`
   （=2000，即偏 1 mm 修 2 mm/s）折算成车体前向修正速度，经
   `heading_base_vx` 汇入航向环统一下发（没开航向保持时直接下发）。
   稳态残差 = 漂移速率/增益 ≈ 2~3 mm，对比开环的 26~35 mm。
   修正量限幅 `WHEEL_SMOKE_STRAFE_CORR_MAX_UM_PER_S` = 60000。
3. **到点闭环保持**（新）：到点不再立即 `Wheel_Stop`，先目标清零、闭环保持
   `WHEEL_SMOKE_MOVE_HOLD_MS` = 300 ms，让速度环把滑行 actively 顶住
   （平移会带动轮子转，编码器看得见、环路顶得住），窗口走完才真正断电。
   `MOVE done` 与 `TASK seg` 结算顺延到保持结束后，报的是最终位姿。
   每段多花 300 ms，整圈 +4 s 左右。
4. **横移提速**：`WHEEL_SMOKE_TASK_STRAFE_UM_PER_S` 200000 → **300000**
   （用户要求加快左右运动）。接近段仍是 40 mm/60 mm/s 慢速，到点动量不变；
   位置环把行进中的漂移兜住，提速不直接放大闭合差。

新宏全部在 `wheel_smoke.c` 参数区，带 `#error` 校验；`MOVE` 状态机加了
RUN/HOLD 两阶段（`WHEEL_SMOKE_MOVE_PHASE_*`）。

### 复跑前补丁：横移高频抖动与起停扭转（同日，上板前发现）

用户复跑前反馈：横移全程高频抖动、可见的高频修正，**起步/到点瞬间扭转很大**。
定位出两个原因，都已修：

1. **倒车增益切换被横向修正误触发（主因，上轮引入的回归）**。
   `heading_poll` 每 10 ms 用 `heading_base_vx_um_per_s < 0` 判"倒车"来切换
   增益（Kp×2.3、Ki 0→2）——这本来是给倒车直行设计的。而横向修正恰好写在
   `base_vx` 上、在 0 附近正负摆动：corr 过零就切增益，且切走时**积分不清零**，
   在"倒车模式"攒一截、切回又冻着，棘轮式累积 → 航向环高频抽动 + 扭转。
   修法：新增 `heading_drive_vx_um_per_s`（名义驱动方向，不含修正量），
   倒车判据改看它；`move_start_axis`（FWD=±speed / 横移=0）、慢速段、
   `move_enter_hold`、`move_finish`、`turn_begin_mdeg`、`B` 命令负责维护。
2. **横移沿用原地转的 80 deg/s wz 权限（次因）**。起步/到点瞬间滚轴摩擦
   不对称让车头一甩，航向环用大权限猛修、修过头再甩回，扭转被放大。
   修法：新增 `WHEEL_SMOKE_STRAFE_WZ_LIMIT_MDPS` = 15000（15 deg/s），
   运行时限幅值 `heading_wz_limit_mdps` 在横移段（含到点保持）切到它，
   其余路径保持宏默认 80000。

**验证状态**：已编译（2026-10-28，0 错 0 警），**尚未上板复跑**。判据：
① 重跑 `R` → `TASK`，期望 `closure_mm` 从 (−28,−98) 收敛到 **±30 mm 内**；
② 看横移段 `side_mm`：应从 26~35 掉到 5 以内；若仍大，先把
   `WHEEL_SMOKE_STRAFE_CROSS_GAIN_UM_PER_S_PER_MM` 上调（3000~4000），
   出现横向振荡再回调；
③ 看 `TURN done err_mdeg`：应全部 ≤±500；
④ **横移全程目视应无高频抖动**；起步/到点的扭转应明显变小。若到点仍有
   抖动，先把 `WHEEL_SMOKE_MOVE_HOLD_MS` 从 300 降到 150~200 试
   （保持窗口内速度环对着滚轴粘滑可能有小幅猎振）；
⑤ 横移 300 mm/s 后盯 `S` 的 output 是否逼近 600‰（堵转阈 580‰），
   电池电压低时先降速；
⑥ 整圈耗时会因转身收尾变慢、到点保持各 +300 ms 而略增，属预期。

## 九、路线 v0.6「全前进」定案（2026-10-28）

满载（上底板+机械臂）实测：**横移/倒退驱动力严重不足**；卸载后消失；只放上
底板（未紧固）仍偏、幅度略小。机理：横移/倒退的力经 45° 滚轴传给地面、
大小 ∝ 各轮法向压力，载荷不均 → 合成力矢量偏斜 + yaw 力矩；反向对角两轮
占空比约为正向的 2.3 倍，满载顶住 600‰ 限幅后运动学散架走斜；且轮编码器
看不到"滚轮-地面"打滑（原理性盲区，软件闭环救不了欠账）。机械结构已定死
不可改，用户决定：**除几何必需外全部运动改为前进**，并解除"工作区旁禁转身"
约束（到站转身扫掠工作区上空可接受）。

路线三版演进：
- **v0.4**（全前进试验，已编译未上板）：被当时认定的三条硬约束否决；
- **v0.5**（臂向必需横移版，32 步，已编译未上板）：保留 9 段臂向必需横移，
  随即被 v0.6 取代；
- **v0.6**（全前进定案，39 步）：本节当前版本。
